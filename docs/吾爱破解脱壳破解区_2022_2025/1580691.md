我是从头直接翻译brainfuck到一个类c的东西，翻译一半就看懂它在干啥了。

`reg++`, `mem[p] = reg;`

`reg++`, `p++`, `mem[p] = reg;`

`p++`, `reg += 60;`

`mem[0] = 1`, `mem[1] = 2;`

`reg = 60`, `p = 2;`

一般来讲，brainfuck每个位置的指针都是比较固定的，不会出现循环中相同语句指针不同的情况。

所以所有的`mem[p]`的`p`都可以直接填上。

这样就发现前面一直是输入无关的，且围绕着`mem[0]`、`mem[1]`、`mem[2]`、`mem[4]`，检查题给的log，`0`、`1`、`4`都是固定的，`2`是变的。

等翻译到`do while`的时候，学过hash的人一眼就能看懂了，就是在做一个`h = (h+c)*base%p`。

所以前面那些翻译都白翻译，就是预处理了一个`base`和一个`p`。

因为给了每步hash的结果，直接爆破每一个字符即可。

一般来讲这种类型的解释器，包括asm类型的vm题，我都是先写出来汇编代码，然后自己手动反汇编写一个C，再把冗余的东西优化下去，比如`r = mem[0], r++, mem[0] = r`这种，就可以写成`r = ++mem[0]`，而且经验来讲，这种`r`一般下一步都不会用的，都是为了算`mem`临时放一下。
