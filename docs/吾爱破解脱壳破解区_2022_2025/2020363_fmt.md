## R3 分析

将`ACEFirstRound.exe`放入IDA分析，在`main`函数可以看到一个虚表，根据里面各个函数内容，将每个虚表函数都重新命名为对应功能。

发现是运行了`ACEDriver`驱动，与`r3`程序之间进行通信。

![1.png](https://attach.52pojie.cn/forum/202503/31/182101quca1wsg8ss4sy5w.png)

![2.png](https://attach.52pojie.cn/forum/202503/31/182104inm5s57d21rld5zz.png)

尝试动调发现没办法，发现程序退出，根据`CheckRemoteDebuggerPresent`的交叉引用发现一个反调试函数。

![3.png](https://attach.52pojie.cn/forum/202503/31/182106xx45888lehmhel5n.png)

找该函数的交叉调用，发现是这边启了一个线程来启动反调试。

![4.png](https://attach.52pojie.cn/forum/202503/31/182108afe7jffmnm6yj7ev.png)

在该函数这边进行条件断点，修改`rip`，让代码直接执行到函数结束处，跳过中间反调试相关代码，即可绕过反调试。

![5.png](https://attach.52pojie.cn/forum/202503/31/182111wx1cjjxz64sjc5mj.png)

动调分析，然后这边输入`flag`要求是以`"ACE_"`开头，然后去掉前面这四个字符，首先进行`Base58`加密，然后再将数据倒转。这边`Base58`是变表，和标准不一样，提取得：`abcdefghijkmnopqrstuvwxyzABCDEFGHJKLMNPQRSTUVWXYZ123456789`

![6.png](https://attach.52pojie.cn/forum/202503/31/182113ljmsk1cmscc777zb.png)

与`"sxx"`进行循环`xor`。

![7.png](https://attach.52pojie.cn/forum/202503/31/182115gbf17ffbakzfaeqn.png)

最后通信发送到`ACEDriver`，命令码是`0x154004`。

## R0 分析

IDA载入`ACEDriver.sys`，发现有几个消息的`Callback`，但是跳转过来发现有混淆和花指令。

![10.png](https://attach.52pojie.cn/forum/202503/31/182121ygb9etmmmj2jjz9y.png)

![11.png](https://attach.52pojie.cn/forum/202503/31/182123dw2quyvsyuzqcvpu.png)

该驱动的混淆和花指令都是一个类型的，花指令是最基础的。

以下图为例子：

对`41e9`按`u`再跳过`e9`字节按`c`还原，即可pass花指令。

![12.png](https://attach.52pojie.cn/forum/202503/31/182125fnpk8k4g293znwd4.png)

然后截图处是一块，将地址计算完进行`jmp`，计算出来实际就是`jmp`到下面`pop`处，说明这一段是无用的，可以直接将`push`到`pop`全部`nop`即可。其他地方都和这地方混淆差不多类型，都直接跳过花指令后`nop`即可。

![13.png](https://attach.52pojie.cn/forum/202503/31/182127gyx51ygxueexn0u6.png)

![14.png](https://attach.52pojie.cn/forum/202503/31/182130loqfqgogsa8zssoo.png)

但有一种比较特殊，并不是跳转到下面邻近代码处，而是`jmp`到其他代码处，观察`push`和底下`pop`寄存器是否一致就可以判断是哪一种类型，该种就得手动计算地址然后写`jmp`。

手动去除大部分混淆后，就可以看到几个回调的里面代码，`MessageNotifyCallback`里面的代码如下：

![15.png](https://attach.52pojie.cn/forum/202503/31/182134gvk22v4zkkvd4pz3.png)

![16.png](https://attach.52pojie.cn/forum/202503/31/182136hy55ayxxzhzhz1z5.png)

进入`call`发现就是关键处，`unk_140004064`那边就是`flag`密文，使用的是`tea`加密，`key`是`['A','C','E','6']`，然后边加密边判断密文是否相等。

## 修改后的魔改 `tea` 加密

即可编写得到对应的解密代码：

```
void tea_decrypt(unsigned int* Input, int* Key)

{

    unsigned int v6 = Input[0];

    unsigned int v8 = Input[1];

    unsigned int sum = 0;

    // sum从32开始

    sum = (-0x61C88647) * 32;

    for (int i = 0; i > 11) & 3]) ^ (v6 + ((v6 > 5)));

        v6 -= (sum + v8) ^ (Key[0] + (v8 > 5));

        sum += 0x61C88647;

    }

    Input[0] = v6;

    Input[1] = v8;

}
```

进行对 `unk_140004064` 密文解密即可，不过注意一点，这边是从 `-1` 处开始判断，也就是 `unk_140004064-4` 处开始是密文。
