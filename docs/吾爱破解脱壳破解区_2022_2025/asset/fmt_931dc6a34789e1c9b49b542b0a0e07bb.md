## 缺少引用与入口点问题

缺少引用就是按描述的添加就行了，程序不包含适合于入口点的静态 `Main` 方法。AI 说：WPF/Windows 应用特殊处理：WPF 的入口点通常由 `App.xaml` 自动生成（对应 `App.g.cs`），无需手动定义 `Main`。若需自定义入口，需设置 `StartupUri` 并确保 `App.xaml` 的生成操作是 `ApplicationDefinition`。然后它给出的是在 `App.xaml` 中添加 `mainwindows`，然后再从 `ilspy` 中查看 `app.cs` 中，发现末尾部分有下面的代码：

```csharp
        [GeneratedCode("PresentationBuildTasks", "4.0.0.0")]
        [DebuggerNonUserCode]
        public void InitializeComponent()
        {
                if (!_contentLoaded)
                {
                        _contentLoaded = true;
                        base.Startup += Application_Startup;
                        Uri resourceLocator = new Uri("/ParkingManage;component/app.xaml", UriKind.Relative);
                        Application.LoadComponent(this, resourceLocator);
                }
        }

        [DebuggerNonUserCode]
        [GeneratedCode("PresentationBuildTasks", "4.0.0.0")]
        [STAThread]
        public static void Main()
        {
                App app = new App();
                app.InitializeComponent();
                app.Run();
        }
```

这两个函数，在项目中缺少。于是添加进去，并且 `GeneratedCode` 要改成 `System.CodeDom.Compiler.GeneratedCode`，然后又出一个错为：以下方法或属性之间的调用具有二义性：`App.InitializeComponent()` 和 `App.InitializeComponent()`。

## 结论与经验总结

对于 WPF 的 C#，多次尝试不同的工具导出不同的工程：

- `.net Reflector` 在工具中能看到 `xaml` 资源文件，但是不能保存，可能是没有设置正确吧。
- `dnspy` 在工具中不能看到资源文件，也不能保存到工程中。
- `ILSPY` 导出 C# 兼容最好。
- 虽然在 `Die` 中检测为 VB 的语言，但是用 C# 还是最好用的。
- `Detect It Easy` 中检测出的 `(Heur)保护: Obfuscation[Modified EP]` 实际上并没有加壳。看了下它的源码，好像是如果缺少引用就会提示这个 `[Modified EP]`，不知是否正确。
