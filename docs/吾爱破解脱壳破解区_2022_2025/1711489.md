```
3> FSOP

FSOP的核心思想就是劫持 _IO_list_all 的值来伪造链表和其中的 _IO_FILE 项，但是单纯的伪造只是构造了数据还需要某种方法进行触发。

FSOP选择的触发方法是调用 [//code.woboq.org/userspace/glibc/libio/genops.c.html#_IO_flush_all_lockp" target="_blank" rel="noopener noreferrer nofollow"](https://code.woboq.org/userspace/glibc/libio/genops.c.html#_IO_flush_all_lockp:rel="nofollow noopener" href="https)，

这个函数会刷新 _IO_list_all 链表中所有项的文件流，相当于对每个 FILE 调用 fflush，也对应着会调用 _IO_FILE_plus.vtable 中的 _IO_overflow

```

```
3> glibc 由于位于 libc 数据段的 vtable 是不可以进行写入的，所以我们只能伪造 vtable

伪造 vtable 劫持程序流程的中心思想就是针对 _IO_FILE_plus 的 vtable 动手脚，通过把 vtable 指向我们控制的内存，并在其中布置函数指针来实现。

3> 2.24 _IO_OVERFLOW 中加入 [//code.woboq.org/userspace/glibc/libio/libioP.h.html#IO_validate_vtable" target="_blank" rel="noopener noreferrer nofollow"](https://code.woboq.org/userspace/glibc/libio/libioP.h.html#IO_validate_vtable:rel="nofollow noopener" href="https) 对 vtable 做了检测，

vtable 必须要满足在 __stop___IO_vtables 和 __start___libc_IO_vtables 之间，而我们伪造的vtable通常不满足这个条件。

但是我们找到一条出路，那就是 [//code.woboq.org/userspace/glibc/libio/strops.c.html#_IO_str_jumps" target="_blank" rel="noopener noreferrer nofollow"](https://code.woboq.org/userspace/glibc/libio/strops.c.html#_IO_str_jumps:rel="nofollow noopener" href="https) 与 [//code.woboq.org/userspace/glibc/libio/wstrops.c.html#_IO_wstr_jumps" target="_blank" rel="noopener noreferrer nofollow"](https://code.woboq.org/userspace/glibc/libio/wstrops.c.html#_IO_wstr_jumps:rel="nofollow noopener" href="https) 就位于二者之间，

所以我们是可以利用他们来通过 IO_validate_vtable 的检测的，只需要将 vtable 填成_IO_str_jumps 或 _IO_wstr_jumps 就行。
```
