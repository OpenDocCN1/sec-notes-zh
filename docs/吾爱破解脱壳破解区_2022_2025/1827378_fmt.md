## 背景

故事的主角是一款国产自托管网盘，它的专业版其实提供了低于5账号的无限试用，启动时也就在日志里说一下你没有license而已。虽然很没有必要，但是我还是想研究一下背后的原理。其实这是挺久之前的事了，但最近该软件推出了新版，包含了一些有用的新功能，故写下基于旧版的研究结果。

该软件支持通过`docker`方式部署，为了方便，就研究了`docker`版本，其他的应该是大同小异。

因为已经过去了很久，以前用Snipaste贴的方便自己看的图基本已经丢了，并且本站传图本来就有点费劲，还有就是我觉得这个没有图也看得明白，并且我懒得重新截图了（主要原因XD），所以本文没有图，不过我相信想学习复现的朋友靠自己摸索也能很简单的实现，毕竟这个东西可能为了性能考虑，似乎压根没上什么保护措施。

### 确定目标

首先通过阅读官方文档，可以发现它的授权是通过一个放置在`/opt/******`目录的`******-license.txt`的文件实现的。于是，只需要确定容器内众多的二进制和脚本文件有哪些读取了这个文件就可以确定我们本次研究的目标。

从官方的仓库中可以看到更旧版本的`******-license.txt`的格式如下：

```
#****** server licence

Name = "Test"
Licencetype = "User"
LicenceKEY = "1410693621"
ProductID = "****** server"
Expiration = "****-*-**"
MaxUsers = "10"
Mode = "subscription"
Hash = "hash value"
```

看起来还真的是够直球的，`LicenceKEY`感觉像是签发时间的时间戳，校验的自然就是`Hash`咯。

虽然是旧版，想来应该是大差不差的，创建好了并且修改好过期时间之类的之后，放在指定位置，然后就是`******`，启动!

呃，当然是启动不起来。。。提示`No hash2 field in license.`，显然是改过了。

那就改成`Hash2`，当然仍然不行，错误二连击。

```
Invalid license!

License hash mismatch. Have you modified the license file?
```

那不然呢，我已经不是modified了，根本就是瞎编的吧。

### 动态调试

通过`docker-compose.yaml`创建好容器后，进入容器发现无法直接启动主程序，提示缺少各种`.so`依赖，但明明这容器启动的好好的呀。仔细观察其启动脚本，发现这一行：`LD_LIBRARY_PATH=$******_LD_LIBRARY_PATH ${****_server} -c "${default_ccnet_conf_dir}" -d "${default_******_data_dir}" -F "${central_config_dir}"`，于是在通过`docker cp`命令把IDA的`linux_server`放进容器并启动，并在IDA的调试选项里加入`LD_LIBRARY_PATH`终于可以动态调试了。

结论就是这东西压根没怎么变，除了`Hash2`字段，只要没有的字段，那就是没限制。比如那个`Board UUID`，压根不用关心怎么计算的，只要你不写那就是不绑定。

## 研究结果

根据从IDA得到的信息，可以知道`******-license.txt`的格式如下：

```
#****** server licence

Name = "***"
Licencetype = "User"
LicenceKEY = "16***92***"
ProductID = "****** server"
Expiration = "20**-**-**"
MaxUsers = "***"
Mode = "life-time"
Hash2 = "34c288adf**************************************************************c56f64*********************************************************************603fec********************************************************************97ad58*********************************************************************15ef6b***********************************************************************a852**********************************************************************ca463eb9e85e6b0298c67acb58184cd55a21158e09a6cf6d7d8799fba2a83215b7"
```

接下来就是生成可以用的`******-license.txt`了。

首先自然是先生成一对公私钥对，代码如下：

```
from Crypto import Random
from Crypto.PublicKey import RSA

def gen_rsa_key_pair():
    random_generator = Random.new().read
    rsa = RSA.generate(2048, random_generator)

    # 生成私钥
    private_key = rsa.exportKey()
    print(private_key.decode('utf-8'))

    # 生成公钥
    public_key = rsa.publickey().exportKey()
    print(public_key.decode('utf-8'))

    with open('rsa_private_key.pem', 'wb') as f:
        f.write(private_key)

    with open('rsa_public_key.pem', 'wb') as f:
        f.write(public_key)

if __name__ == '__main__':
    if(input()=='Y'):
        gen_rsa_key_pair()
```

其中`Hash2`通过如下代码生成:

具体过程的简单解释就是先把除了`Hash2`的所有字段和值都拼在一起，然后再拼上`677*****dc6bc*****e653a*****bcb*****21c3`这个不知道哪来的看起来像是md5 hash一样的东西，然后用私钥调用`RSA_private_encrypt`加密，得到的Bytes再编码成特定的字符串就得到了`Hash2`。

```
with open("******-license-example.txt", 'r') as f:
    lines = f.readlines()
lines2 = lines[2:10]
tmp = []
for l in lines2:
    a, b = [i.strip() for i in l.split("=")]
    b = b.strip("\"")
    if b != "":
        tmp.append(a)
        tmp.append(b)
tmp = "".join(tmp)
tmp = tmp + "677*****dc6bc*****e653a*****bcb*****21c3"  #这是不知道哪来的magic number
hash_tmp = sha1(tmp.encode()).hexdigest()
#raw_rsa = rsa_private_encrypt(hash_tmp)
print(hash_tmp)
private_key = RSA.import_key(open('rsa_private_key.pem').read())
raw_rsa = encrypt_pem(hash_tmp, private_key)
#print(raw_ash2)
hash2 = encode_rsa_sign(raw_rsa)
#hash_decode = decode_rsa_sign(hash2)
#assert hash_decode == raw_rsa
print(hash2)
s="Hash2 = \"{0}\"\n".format(hash2)
l=lines[:12]
l.append(s)
with open("******-license.txt","w") as f:
    tt="".join(l)
    f.write(tt)
```

其中`encrypt_pem`必须采用`openssl`库里`RSA_private_encrypt`相同的实现，我因为不太懂Python这东西具体的参数怎么调，调了半天还不行就直接C语言写了个小程序直接调用`RSA_private_encrypt`做了这件事，只需要调用下`PEM_read_RSAPrivateKey`和`RSA_private_encrypt`就好，pading模式为`RSA_PKCS1_PADDING`，所以上面的代码压根是不能直接用的。

其中`encode_rsa_sign`的代码为：

```
def encode_rsa_sign(rsa_result):
    #########根据不知道为什么混在****-server里的不知真假的lic生成函数实现
    m = "0123456789abcdef"
    b_arr = []
    for b in rsa_result:
        a1 = b & 0xF
        a2 = b >> 4
        b_arr.append(m[a2])
        b_arr.append(m[a1])
    return "".join(b_arr)
```

最终结果可以登录web管理界面后在系统管理-系统信息里看到，形如

企业版 永久授权给 `${Name}`，技术支持服务至 `${Expiration}` 到期

的样子，就算是成功了。

## 最终成品

为了方便部署和使用，我把这东西做成了一个脚本，方便在部署容器后一键启动。

包含自动Patch Public Key 和 自动释放`******-license.txt`到指定位置。

隐去关键信息后的脚本如下：

```
#/bin/bash
/opt/******/******-server-latest/******.sh stop
echo "=============STOP ****** SUCCESS!!======================="
****_PATH=/opt/******/******-server-latest/******/bin/****-server
OFFSET=$(($(grep --byte-offset --only-matching --text -P "(?=\-{4}).*BEGIN"  $****_PATH  |grep -P "\d+" -o)))
echo "===========PUBKEY FOUND!!! OFFSET  $OFFSET  =============="
MAGIC=$(cat
```

脚本很简单，就不解释了。里面用到的命令容器自带，不用另外安装

## 后记

可能有的朋友注意到`#########根据不知道为什么混在****-server里的不知真假的lic生成函数实现的注释`，其实这个文件里有个印象中没有引用的符号，里面差不多就是做了与解析授权差不多相反的事情，不知道是不是官方把`Makefile`之类的写错了，导致这个符号被错误地编译到最终结果里，所以，其实有一种很简单的方法，就是你只需要写一个`frida`脚本，`spawn`模式启动下`****-server`，然后修改指定位置的内存，最后用特定的参数主动调用这个符号，你就可以直接得到`Hash2`，应该比我这个方法快很多。
