
# [原创] 对于某云课堂密码的分析

- 原帖：`https://www.52pojie.cn/forum.php?mod=viewthread&tid=1757193`
- 抓取时间：2026-11-01T22:58:56

## 背景与思路

学校机房运用了某公司的云课堂，属于同一服务器分机只做显示输入且终端无硬盘的类型。终端在启动时可以打开设置，但是需要密码。观察到 windows 内的学生管理软件与该系统属于同公司，并且也存在设置密码。猜测二者密码可能互通，决定分析该程序来寻找可能的密码。

由于机房电脑配置实在太低，决定先从行为上分析密码相关的文件或注册表。

## 行为分析

捕捉到大量相关行为，先筛选出该公司旗下的软件，发现了大量的操作。进一步筛选 UI 所在的进程（当时不确定是不是读密码的，相关进程太多了，只能挨个尝试）。

![软件在运行时的行为（约5s后）](https://attach.52pojie.cn/forum/202303/12/085025wiumiemizzm5zmf0.png)

![清空后打开设置](https://attach.52pojie.cn/forum/202303/12/085156o4mykqgk16dg11m6.png)

观察到大量读取了 `mmr.ini`，打开文件后，文件未加密但没有密码相关内容，部分内容如下：

## 发现密码文件

随机输入密码尝试，发现除了上述操作和输入法操作外出现了新的文件：

![输入密码](https://attach.52pojie.cn/forum/202303/12/085722o3o9jgyg027djsyg.png)

打开文件，内容如下（密码部分隐藏）：

```text
4f6f58e044********e6e04e2c9fc04
```

盲猜 md5，将 `123456` 的 md5 导入覆盖（疑似的密码文件都没有保护，普通权限直接保存了:rggrg ），打开设置测试：

![设置](https://attach.52pojie.cn/forum/202303/12/090016xjupnn86nslunlhn.png)

## 验证与结论

很好，密码直接 md5 处理都没加盐就保存了，文件还一点都没有保护。

接下来就是 md5 反查，somd5 免费查询找到了原密码，就是软件公司的网址.........

经检验确定密码互通，学校不让带手机，那个状态截不了图。
