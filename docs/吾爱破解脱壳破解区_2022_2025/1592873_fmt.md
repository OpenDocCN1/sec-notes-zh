## 4. 查看按钮其他逻辑事件

![image-20220224115155023.png](https://attach.52pojie.cn/forum/202202/24/140228r6qxxxiqv4e3xec4.png)

### 跑完 `GetDlgItemTextA` 函数后发现往下有一个 `ExitProcess` 的函数

这让我们联想到了我们正常运行程序时输入 `12345678` 程序结束运行，那可以肯定这个函数就是在我们输入 `12345678` 按下 `Crack` 按钮触发的。从这个函数往上看，发现在这个函数之前有个 `jbe` 跳转，点击一看，如果跳转便是跳过这个 `ExitProcess` 的执行，说明这个 `jbe` 是一个关键点。那我们对 `jbe` 这个跳转的条件 `cmp eax,0x6` 进行断点分析。

![image-20220224115918765.png](https://attach.52pojie.cn/forum/202202/24/140301tnpypfpmlppfapza.png)

### `jbe` 的条件是对比 `eax` 的值是否小于等于 `0x6`

如果满足，则跳过退出程序函数。我们一看 `eax` 的值便是我们输入 `12345678` 的长度，那我们重新输入六个数 `123456` 作为用户输入的值运行到这里。

![image-20220224120252999.png](https://attach.52pojie.cn/forum/202202/24/140317pjz733xb3jd2x3o2.png)

### 果然，`eax` 此时确实是用户输入的长度，而且 `jbe` 跳过了退出

`ecx` 存入了我们输入的 `123456`，但是是以字符串形式存入（这里要注意，后面会用到）。那我们继续走跳过退出后的代码。

![image-20220224121528799.png](https://attach.52pojie.cn/forum/202202/24/140334epqr2ptrdtqliiix.png)

### 经过这个函数后，`eax` 的值变为了 `0x1e240`

我们再看这个 `call` 的参数只有一个 `ecx`，那在这个 `call` 之前我们知道 `ecx` 的值是字符串 `"123456"` 的地址，那说明这个 `0x1e240` 和这个 `123456` 有关系，一个是字符串一个是十六进制。这个我们就可以猜想是否这个 `0x1e240` 是 `"123456"` 转换的十六进制数，那我们用代码验证一下：

```
#include <stdio.h>
#include <stdlib.h>

int main()
{
    char num[6] = "123456";
    int last = atol(num);
    printf("%x", last);
}
```

![image-20220224122700402.png](https://attach.52pojie.cn/forum/202202/24/140352hgn32wpcg8y2n0nk.png)

果然，我们的猜想是正确的，那继续往下走。

![image-20220224122817429.png](https://attach.52pojie.cn/forum/202202/24/140403xz0knb7832k30sh8.png)

这几行代码将 `eax` 的值赋值给了 `edx`，而且 `edx` 还加 1。此时还出现了一个 `jnz` 跳转，跳转的条件是 `edx` 的值是否等于 `0x7b`，不等于则跳转。我测试了一下，跳转后的流程是重复执行获取用户输入，所以我们为了不结束程序，则要使得 `edx` 等于 `0x7b`，也就是说需要 `eax + 1 = 0x7b`。我们刚才分析过 `eax` 是我们输入字符串转成的十六进制数，那我们此时可以得知 `eax = 0x7b - 1`（字符转十六进制数），最后可以用代码算出我们要输入什么。这里要强调一个问题：从对 `GetDlgItemTextA` 断点以来，我们输入的变化情况是 `123456`（整数）-> `"123456"`（字符串）-> `0x1e240`（十六进制数），其实我们输入的就是经历了两个函数 `itoa()` -> `atol()`。所以这里我们可以直接得知我们输入要满足其等于 `0x7b - 1`，所以就是数字 `122`。那我们重新打开程序，断点在上图这个 `cmp`。

![image-20220224125341928.png](https://attach.52pojie.cn/forum/202202/24/140501dizs2p2y2jcy52bb.png)

此时的确可以了，`jnz` 不会跳转了，也就不会走程序结束的流程了，继续往下走。

![image-20220224125718380.png](https://attach.52pojie.cn/forum/202202/24/140528obz18f5aj91x9s59.png)

![image-20220224131625392.png](https://attach.52pojie.cn/forum/202202/24/140609kaag7ggzag900aha.png)

此时，下面又出现了三个接连的对比，分别是地址 `ss:[ebp-0x101]`、`ss:[ebp-0xFF]`、`ss:[ebp-0x100]` 的值分别和 `0x78`、`0x7a`、`0x79` 对比。这三个 `jnz` 经过测试都是跳转到重复执行获取用户输入和这一系列的判断。那此时我们来分析这三个地址的特殊性，发现我们刚才输入那三个数 `122` 的地址是 `ss:[ebp-0x108]`，第一个地址在 `122` 地址往后 3 个字节，第二个地址在 `122` 地址往后 1 个字节，第三个地址在 `122` 地址往后 2 个字节。那这三个地址的值到底来自哪里呢？我们知道这个 `Crack` 的第一个要求便是用户输入的值小于等于 6，说明我们可以输入 6 个长度的任意字符，那剩下的这三个字节加上 `122` 的长度刚好是六个。那还不简单？直接找出这三个不满足 `jnz` 跳转的值是多少就行了。

条件：

- `ss:[ebp-0x101] = 0x78`，字符：`z`
- `ss:[ebp-0xFF] = 0x7a`，字符：`x`
- `ss:[ebp-0x100] = 0x79`，字符：`y`

按位置排序出来便是 `xyz`，那我们重新打开输入 `122xyz`，断点最后一个 `jnz`。
