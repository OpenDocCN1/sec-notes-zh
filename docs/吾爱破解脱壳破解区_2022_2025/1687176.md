## 寻找参数

打开直播，在控制台网络可以看到，会有加载一堆的个性化图片。

![](img/044e57285e4edba7ab2aef81c3b839b2.png)

可以先从这些加载的图片调用栈入手，往回分析。至于为什么从这些图片下手？因为这些个性化图片的加载是伴随 `danmu` 消息一起出现的。按照正向的思路去反推，消息和图片一般是会在一个共同的响应体里面。

![](img/d2abd0366c4e56eaac6c255856b43b12.png)

随便选择一张图片，进到调用栈里面。

![](img/441b3f4742d333f46875265bf353b3ff.png)

`F8` 运行，多运行几次之后，会发现这里会有消息内容出来，这也就验证了我们之前的想法。

![](img/1498b444790f7ccfc8ec9ee2d5f0e83a.png)

![](img/a25bf0472d2f9ece10cd019f0d911018.png)

![](img/ea19a21cb2abbd5b5e2e281a95ad422e.png)

这里显示的消息，是经过解析之后的内容。可以直接到调用栈最开始的位置，然后往回找线索。下图可以看到，它是一个 `setInterval` 定时器。

![](img/4d4e489bc29136dcd02a3ab734bee9b5.png)

在上面，可以看到 `key` 名称为 `sdkinit` 初始化。

![](img/43dfeff1457e7b4887f3063a192a2498.png)

通过分析，他的消息处理顺序如下。

![](img/6657c734088cd76e4f80606046f3744d.png)

![](img/490f20abe94b736b9f92361773e09327.png)

到了这一步，可以直接 hook 这个 `this`，然后重写 `publishSync`。

```
window._a_ = a;

var publishSync_ = window._a_.publishSync;

window.__a__.publishSync = (i) => {  // 这里用箭头函数，不要用function
    let obj = i.payload;
    console.log(obj);
}
```

![](img/e148c5a13479294cd25fdc750169abf0.png)

成功之后，就会有下面的效果。

![](img/5a713aecb25f168875b72e94a2ab41f9.png)

到了这一步，写一个 `wss` 服务端，将获取到的消息共享出去。

```
function hookFunc (o) {

    if (_WSS_.readyState === _WSS_.OPEN) {

        _WSS_.send(JSON.stringify(o))

    };

};

var _WSS_ = new WebSocket('wss://x.x.x.x:10086');

window._a_ = a

var publishSync_ = window._a_.publishSync;

window._a_.publishSync = (i) => {  // 这里用箭头函数，不要用传统function

    if (_WSS_.readyState === _WSS_.OPEN) {

        _WSS_.send(JSON.stringify(i)) // WSS服务端和数据解析可自行编写，或后台私我获取，此处不做演示

    };

}
```
