## 三、现在才开始逆向分析（后面烂尾了）

程序是提取出来了，那么如何分析呢？

在官网文档[DS_TLSR8258-E Datasheet](https://wiki.telink-semi.cn/doc/ds/DS_TLSR8258-E_Datasheet%20for%20Telink%20BLE+IEEE802.15.4%20Multi-Standard%20Wireless%20SoC%20TLSR8258.pdf) PDF第37页有关架构的描述：

```
2.3 MCU

The TLSR8258 integrates a powerful 32-bit MCU developed by Telink.
The digital core is based on 32-bit RISC,and the length of instructions is 16 bits;
four hardware breakpoints are supported.
```

所以Telink `TLSR8xxxx`的数字核心基于32位RISC，指令长度为16位（官方命名：`TC32`）。

### 1、下载`TC32-GCC`编译器

从刚刚Github上Ai-Thinker-Open其中的教程中下载编译器：[tc32_win.rar](http://shyboy.oss-cn-shenzhen.aliyuncs.com/readonly/tc32_win.rar)

### 2、正向编译个Demo

那么从官方或者Ai-Thinker-Open的SDK中编译一个Demo（编译过程略，用vscode+Ai-Thinker-Open的SDK挺方便的），那么将会生成`ELF`和`BIN`文件，然后使用`TC32-GCC`编译器附带的`tc32-elf-objdump.exe`反汇编`ELF`文件：

比如我这里编译生成了个`8258_ble_remote.elf`文件。

```
tc32-elf-objdump.exe -D ./8258_ble_remote.elf > ./asm.txt
```

这样我们打开`asm.txt`文件，就可以看到汇编代码了。

### 3、逆向方法1：直接猜

比如我们从`asm.txt`中得知出栈指令对应的机器码（telink所有的汇编代码都在前面加了个“`t`”）：

```
6cff  tpop  {r0, r1, r2, r3, r4, r5, r6, r7}

6c3c  tpop  {r2, r3, r4, r5}

6df0  tpop  {r4, r5, r6, r7, pc}

6d10  tpop  {r4, pc}
```



# `tpop` 寄存器机器码编号

```
6cf0  tpop  {r4, r5, r6, r7}
```

那么可以直接分析出 `pop` 寄存器对应的机器码编号：

（有 `pc` 寄存器和没有 `pc` 寄存器就是 `6c` 和 `6d` 区别）

如：

```
6df0 tpop {r4, r5, r6, r7, pc}
```

|  |  |
| --- | --- |
| `r7` |  |
| `r6` |  |
| `r5` |  |
| `r4` |  |
| `r3` |  |
| `r2` |  |
| `r1` |  |
| `r0` |  |
|  |  |
|  | `1` |
