
## X.509证书——证书注销

- 每个证书都有有效期
- 证书在超期之前可能被注销
  1. 用户私钥不安全
  2. 用户不再信任该CA
  3. CA证书的安全性受到危害
- CA维护被注销证书的列表
  - Certificate Revocation List (CRL)

## X.509证书——证书验证

- 实体A的证书验证
  - 检查该证书的有效期和注销列表
    - 保证该证书没有过期或被注销
  - 构造证书链
    - 保证每个CA证书没有过期或被注销
  - 如果证书链中存在可信CA的证书，则信任A
    - 表明A的证书是由可信的CA签发的

## PGP

- 由Phil Zimmermann等人提出
  - 选择了当时可获得的最好的密码算法
    - RSA、DSS、Diffie-Hellman
    - CAST-128、IDEA和3DES
  - 独立于操作系统和处理器，只依赖于一个易用的小规模指令集，因此易于在各种平台实现
    - Unix, Windows, Macintosh等
  - 提供了各种免费版本，其商用版本能够得到技术支持服务
  - 不由任何政府或标准制定机构控制
  - 已经成为了Internet标准文档（RFC 3156）

## PGP——符号约定

- Ks = 会话密钥
- KRa = 用户A的私钥
- KUa = 用户A的公钥
- EP = 公钥加密
- DP = 公钥解密
- EC = 对称加密
- DC = 对称解密
- H = hash函数
- || = 串联
- Z = 用ZIP算法压缩
- R64 = base64编码（基数64编码）

## PGP服务——认证

过程描述：

1. 发送方创建消息
2. 用SHA-1生成消息的160-bit的hash码
3. 用发送方的私钥按RSA加密hash码并将结果放入消息中
4. 接收方使用发送方的公钥按RSA解密，恢复hash码
5. 接收方从消息中生成新的hash码，并与解密得到的hash码比较。如果匹配，则接收到的消息是真实的

## PGP服务——保密

过程描述：

1. 发送方生成消息和作为会话密钥的128-bit随机数
2. 用会话密钥按CAST-128（或IDEA、3DES）加密消息
3. 用接收方的公钥按RSA加密会话密钥，放入消息中
4. 接收方使用其私钥按RSA解密，恢复会话密钥
5. 使用会话密钥解密消息

## PGP服务——保密和认证

过程描述：

1. 用发送方的私钥创建签名，并附加到消息中
2. 用会话密钥加密消息和签名
3. 用接收方的公钥加密会话密钥，并附加到消息中

## PGP服务——压缩

- 压缩将减少电子邮件传输和存储成本
  - PGP默认进行压缩
  - 压缩算法：ZIP

- 压缩原则
  - 在签名之后
    - 方便验证为压缩的消息。否则，将每次验证消息签名时，都需要对消息进行压缩
    - 即使允许动态压缩消息进行签名验证，但由于PGP中压缩算法允许根据运行环境自动调整速度和压缩比，这将导致消息摘要发生变化，因此，比较困难
  - 在加密之前
    - 可加强密码的安全性。压缩后消息的冗余信息减少，密码分析更加困难

## PGP服务——电子邮件兼容性

- 原因
  - PGP需要发送二进制数据
    - 加密的消息
    - 消息的签名
  - 可是，许多电子邮件系统仅允许使用由ASCII码组成的
    消息
  - 因此，PGP必须能够将二进制数据编码为可打印的
    ASCII码字符
- 编码方法：base64（基数64）
  - 将3个字节编码为4个可打印字符
    - 该编码方法将使消息大小增加33%
  - 如果结合消息压缩，实际消息大小将减少
    - 1.33（编码）*0.5（压缩）*X（消息）
      =0.665*X
