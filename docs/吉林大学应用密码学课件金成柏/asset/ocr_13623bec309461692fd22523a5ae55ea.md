# 数字签名——仲裁数字签名

Notation:

+   - X = sender
+   - Y = recipient
+   - A = Arbiter
+   - M = message
+   - T = timestamp

| (a) Conventional Encryption, Arbiter Sees Message |
|(1) X → A: M || E_KxA [ID_X || H(M)] |
|(2) A → Y: E_KAY [ID_X | M || E_KXA [ID_X || H(M)] || T] |
|(b) Conventional Encryption, Arbiter Does Not See Message |
|(1) X → A: ID_X || E_KXY [M] || E_KXA [ID_X || H(E_KXY [M])] |
|(2) A → Y: E_KAY [ID_X || E_KXY [M] || E_KXA [ID_X || H(E_KXY [M])] || T] |
|(c) Public-Key Encryption, Arbiter Does Not See Message |
|(1) X → A: ID_X || E_KR_A [ID_X || E_KU_Y (E_KR_X [M])] |
|(2) A → Y: E_KR_Y [ID_X || E_KU_Y [E_KR_X [M]]] || T |

# 数字签名方法

+   - (a) 传统加密，仲裁者能阅读消息
+     - X和Y必须高度信任A
+     - 问题: A可能伪造X的签名（有利于Y），也可能否认X的签名（有利于X）
+   - (b) 传统加密，仲裁者不能阅读消息
+     - X和Y必须高度信任A
+     - 问题: A可能与Y伪造X的签名（有利于Y），也可能与X否认X的签名（有利于X）
+   - (c) 公钥加密，仲裁者不能阅读消息
+     - 解决了上述问题
