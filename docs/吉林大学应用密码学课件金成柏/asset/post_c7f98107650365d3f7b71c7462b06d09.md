
## Feistel密码结构的设计动机

- 问题
  - 当分组较大时，密钥长度规模非常大
    - n=4时，密钥长度为n* 2^n = 64
    - n=64时，密钥长度为n* 2^n = 2^70
- 观察
  - n-bit分组密码的理想密钥长度需要n* 2^n
    - 最大可能的密钥数量为(2^n)^2^n
  - n-bit分组密码的加密/解密可逆时
    - 密钥空间大小为(2^n)!

### 解决方法
- 较少密钥长度——考虑密钥空间的子集
  - 例如：n=4时，定义如下线性映射（类似Hill密码），密钥大小为n²=16
    - y1 = k11x1 + k12x2 + k13x3 + k14x4
    - y2 = k21x1 + k22x2 + k23x3 + k24x4
    - y3 = k31x1 + k32x2 + k33x3 + k34x4
    - y4 = k41x1 + k42x2 + k43x3 + k44x4
  - 上述线性系统是较容易攻破的
- 弱化统计特征（考虑非线性系统）

## Feistel密码——S-P网络（SPN）

- 代换置换网络（substitution-permutation networks）
  - 1949 Claude Shannon 提出了这个概念
  - 代换置换乘积密码
  - 奠定了现代分组密码学的基础
    - Feistel密码机构就是基于这种形式
- 基于两个原语操作
  - *substitution* (S-box)
  - *permutation* (P-box)
- 支持混淆（diffusion）与扩散（Confusion）

## Feistel密码——密码结构

- Horst Feistel 设计了 feistel 密码
  - 基于乘积密码的概念
- 输入分成两部分：左部L0和右部R0
  - n轮迭代处理
    - 每轮迭代具有相同的结构
    - 第i轮迭代的输入Li-1和Ri-1来自于上轮迭代的输出
  - 每轮迭代处理
    - 代换作用于数据的左半部分，通过轮函数F作用数据的右半部分，再与左半部分数据异或来完成
    - 然后，交换数据的左右两个部分完成置换
- 实现了Shannon的SPN概念

## Feistel密码——参数和特征

- 分组长度（block size）
  - increasing size improves security, but slows cipher
- 密钥长度（key size）
  - increasing size improves security, makes exhaustive key searching harder, but may slow cipher
- 迭代轮数（number of rounds）
  - increasing number improves security, but slows cipher
- 子密钥生成算法（subkey generation）
  - greater complexity can make analysis harder, but slows cipher
- 轮函数（round function）
  - greater complexity can make analysis harder, but slows cipher

## Feistel密码——设计原则

- 快速软件加密/解密
  - 不仅易于快速硬件实现，也应易于快速软件实现
- 简化分析难度
  - 设计简单的算法易于分析，从而对算法的安全性和脆弱性有清晰的认识
  - 便于改进算法

## Feistel密码——解密算法

- 算法相同
  - 加密/解密使用相同算法
- 逆序密钥
  - 逆序使用子密钥

## 数据加密标准 (DES)

- 在世界上使用最广泛的分组密码
- 1977年被美国国家标准局——NBS（现在的国家标准和技术研究所——NIST）采纳为联邦信息处理标准46（FIPS PUB 46）
- 采用64-bit数据分组， 56-bit密钥
- 设计上广受争议

## 数据加密标准 (DES)——历史

- IBM开发了Lucifer密码
  - 由Feistel领导的团队
  - 使用64-bit数据分组和128-bit密钥
- 进一步开发了Lucifer密码的修订版本
  - NSA（国家安全局）作为技术顾问参与
  - 适于芯片实现的商用密码产品
  - 密钥长度减小为56-bit
  - 但抗风险能力更强
- 1973年，NBS征求国家密码标准方案
  - IBM提交了修订的Lucifer
  - 1977年被NBS采纳为数据加密标准

## 数据加密标准 (DES)——设计上的争议

- 争议
  - 56-bit密钥长度的选择
    - Lucifer的密钥长度是128-bit
    - 担心密钥长度太短，不能抵抗穷举攻击
  - 设计标准被列入了官方机密类
    - S盒的设计标准
    - 用户不能确信DES的内部结构是没有弱点的，NSA有可能利用这些弱点在没有密钥的情况下解密
- 后来的密码分析工作表明，DES的内部结构是强健的

## DES加密算法——单轮迭代结构

![](img/0935d481fd26d10140d7cd560b6540ba_95_0.png)

Figure 3.8 Single Round of DES Algorithm

- 输入
  - $L_{i-1}$（32-bit）
  - $R_{i-1}$（32-bit）
  - 子密钥$K_i$（48-bit）
- 输出
  - $L_i = R_{i-1}$
  - $R_i = L_{i-1} \text{ XOR } F(R_{i-1}, K_i)$
- 轮函数F的处理过程
  - 使用扩充置换E将$R_{i-1}$扩充为48-bits
  - 与子密钥$K_i$与或
  - 通过8个S代换盒处理得到 32-bit输出
  - 最后进行32-bit的置换函数P
