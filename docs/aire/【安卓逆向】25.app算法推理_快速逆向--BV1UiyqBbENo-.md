## 什么是APP算法推理？🔍

首先，我们需要搞清楚一个核心问题：什么是APP算法推理？简单来说，APP算法推理就是在不直接阅读源码的情况下，通过观察APP的运行行为、输入输出数据以及处理流程，推测出内部算法逻辑的一套方法。它不关心APP是怎么写的，也不关心APP外面包了什么壳，它只看APP运行时暴露出来的“痕迹”。

这里可以用一个公式来概括算法推理的基本过程：

```text
算法推理结果 = f(输入数据, 输出数据, 行为特征, 执行流程)
```

其中，输入数据和输出数据是我们可以直接观察到的，行为特征包括内存变化、网络请求等，执行流程则是通过调试或Hook等手段追踪到的调用顺序。

正因为算法推理是基于“运行行为”而不是“源代码”，所以不管APP有没有加固，也不管APP是用何种方式开发的，它是原生的也好，它是H5的也好，它是Flutter开发的也好，算法推理都是有效的。换句话说，只要APP还在运行，它就得把数据吐出来，算法推理就能从这些数据中反推出门道。

## 算法推理的局限性 ⚠️

不过，算法推理并不是万能的。它也有自己的局限性。具体局限性是什么？我们到下节课再说。当你明白了算法推理的原理之后，你就知道了。这里先卖个关子，因为原理清楚了，局限性自然就浮出水面了。

我们只需要记住一句话：算法推理是“从外部观察内部”的黑盒思路，它不需要源码，但也要付出相应的代价。至于代价是什么，下一节课我们会详细展开。

## 实战案例：识别加固壳 🛡️

理论说完了，我们来看一个实际案例。案例是这个APP，这个APP它是有加固的。为了保护代码不被轻易阅读，开发者给这个APP加了一层壳。我们可以用专门查壳的工具去检测它。

查壳工具的工作方式其实就是一个匹配过程，可以用伪代码表示：

```text
function 查壳(应用文件):
    特征库 = [已知壳的签名特征]
    for 特征 in 特征库:
        if 应用文件包含特征:
            return 特征对应的壳名称
    return "未知壳"
```

拿这个APP一查，结果就出来了：它是360的加固。这个结果说明我们的查壳工具识别出了藏在APP外面的保护壳。

但是这里要注意一个问题：这个工具已经很久没有更新了。所以，一些比较新的壳或者一些未知的壳，是查不出来的。因为工具的特征库停留在旧版本，遇到新出现的壳或者极少见的壳，它自然就“看不出来”。当然，有壳的特征是很明显的，即使工具识别不了，我们也可以通过其他特征（比如文件的特殊段、入口点变化）判断出“这玩意儿肯定被加壳了”。
