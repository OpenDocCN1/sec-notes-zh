
# 🧭 网络验证卡密软件逆向教程：第1章：课程概述与学习目标


本课程来自直播回放整理，主题是网络验证卡密软件的逆向分析基础。课程围绕三个核心目标展开：过期卡密复活、简单 VMP 代码混淆还原、某 P 网络验证反调试硬断绕过。课程定位是游戏安全、软件安全、网络安全和 CTF 比赛的基础内容，适合零基础学习者理解逆向分析的基本流程。

从整体流程看，先要理解卡密的长度、格式和服务器校验关系，再定位登录校验函数，然后处理简单的 JMP 垃圾指令混淆，接着绕过过期判断和暗装校验，最后处理 QP 网络验证的硬断检测和调试器附加问题。可以把学习目标概括为下面这个简单形式。

```text
学习目标 = 理解卡密校验 + 还原简单混淆 + 复活过期卡密 + 绕过硬断反调试
```

# 🧰 网络验证卡密软件逆向教程：第2章：实验准备与卡密基础


上一章我们说明了课程目标和法律边界，本章来看看实验准备和卡密基础。直播中打开的程序需要输入卡号，卡密位数不正确时会先做本地校验，然后提示验证失败。常见卡密一般是 32 位，但只输入 32 位乱码仍然可能提示位数不对，这说明程序不只看长度，还会检查卡密格式是否符合服务器校验算法。

正版过期卡密在逆向分析中很有价值。原因有两点：第一，过期卡密的长度符合正版卡密长度；第二，过期卡密的格式符合服务器校验卡密的算法。即使卡密已经过期，它仍然能帮助分析人员避开最基本的长度和格式问题，把精力放到过期判断和登录校验上。

```text
卡密基本条件：
len(card) == 32
format(card) 符合服务器校验算法
```

直播中还讨论了过期卡密被后台清理的问题。如果作者把过期卡密清理掉，用户可能不知道自己是否过期，容易和作者扯皮。这个问题属于网络验证设计层面的取舍，不影响本节理解卡密长度和格式的重要性。

下面按直播演示顺序列出实验准备内容，这些内容能帮助初学者复现后续操作。

- Windows 实验环境，最好放在虚拟机中，便于快照和恢复。
- 调试器工具，例如 DBG 类调试器和 CE，用于附加进程、查看内存和下断点。
- 易语言和超级模块，用于观察 VMP 保护标记的生成方式。
- 一张正版过期卡密，用于避开长度和格式问题。
- 待分析的网络验证程序，以及记录关键地址的笔记。
- 了解 32 位和 64 位程序的区别，64 位程序要用 64 位调试器分析。

这些准备完成后，就可以进入登录校验函数的定位。上一节我们理解了卡密的基本条件，下一节我们来看看怎样找到程序里真正负责登录判断的代码位置。


# 🔍 网络验证卡密软件逆向教程：第3章：定位登录校验函数


上一章我们准备了实验环境和卡密基础，本章来定位登录校验函数。直播中先附加程序，切换到程序主模块，查看当前模块字符串，可以看到与“过期”相关的字符串。字符串只能提供线索，真正关键的是找到登录校验函数的范围。

函数一般有头部和尾部。常见函数头部是保存栈帧，尾部是返回。可以用下面的代码表示这种结构。

```asm
push ebp
mov ebp, esp
; 函数主体
ret
```

直播中在登录按钮附近下断点，点击登录后程序断下来，说明这里确实是登录判断的位置。随后用 F8 单步执行，观察代码一行一行往下走。单步过程中发现一个 JMP 指令，JMP 是无条件跳转，也就是不管条件如何都会跳到目标地址。

```asm
JMP 目标地址
```

因为 JMP 会直接跳到目标位置，所以 JMP 和目标地址之间的一段代码可能永远不会执行。直播中让观众判断这段绿色框住的代码有没有意义，结论是对于当前函数来说，这段代码没有实际作用，它是用来干扰肉眼的垃圾指令。

下面列出定位登录校验函数时可以采用的步骤，这些步骤适合初学者按顺序练习。

- 附加目标程序，切换到主模块。
- 查看当前模块字符串，寻找“过期”“验证失败”等线索。
- 找到登录按钮触发的函数范围，识别函数头和函数尾。
- 在登录判断位置下断点，点击登录触发断点。
- 使用 F8 单步执行，观察跳转指令和代码执行流。
- 复制 JMP 目标地址，在内存窗口跳转过去，确认跳转前后区间。
- 记录关键地址，为后续 NOP 填充和过期判断处理做准备。

定位到 JMP 和垃圾指令后，就可以进入简单 VMP 混淆还原。上一节我们找到了登录校验函数和可疑跳转，本节我们来看看怎样把混淆代码清理干净。

# 🧹 网络验证卡密软件逆向教程：第4章：简单VMP混淆还原


![](img/8cfd39d5cc069cfbd3d93ef1cf8d6c08_3.png)

上一章我们定位到了登录校验函数和 JMP 跳转，本章来还原简单的 VMP 代码混淆。直播中用易语言和超级模块演示了 VMP 保护标记，保护标记开始后会插入跳转和垃圾指令，让调试器里出现大量看不懂的代码。常见现象是一个 JMP 跳过一段区间，区间里出现 outsb、arpl、es 加 62 加 si 之类的乱码指令组合，看起来很不友好。

处理思路很直接：找到 JMP 的目标地址，确认垃圾区间的起点和终点，然后把区间填充为 NOP。NOP 指令的字节是 0x90，执行 NOP 基本等于什么都不做，所以填充后代码会变得干净，阅读起来更舒服。

```asm
; 第一处示例
JMP 0x419B9E
; 垃圾区间
[0x419B8E, 0x419B9E) 填充 0x90

; 第二处示例
; 从 E9 开始的跳转区间到目标地址之前
[跳转起点, 目标地址) 填充 0x90
```

直播中先复制 JMP 目标地址，在内存窗口跳转过去，确认目标位置。然后在跳转起点到目标地址之间右键选择二进制编辑，填充 90。填充后对比左右两边代码，右边明显更干净，真正的代码结构开始显现，例如出现 `[ebp-4]` 这样的局部变量访问。

下面列出简单 VMP 混淆还原的操作步骤，这些步骤针对简单的保护标记有效，复杂混淆需要更系统的学习。

- 找到保护标记开始处的 JMP。
- 记录 JMP 的目标地址。
- 确认垃圾区间的起点和终点。
- 在二进制编辑中把区间填充为 90。
- 检查填充后代码是否恢复可读结构。
- 继续寻找下一处 JMP 和保护标记结尾。
- 对比还原前后的代码，确认真正的业务逻辑出现。

需要注意，NOP 不能乱填。直播中提醒，如果处理不当会造成堆栈不平衡，程序会直接崩溃。简单保护标记可以这样处理，复杂 VMP 需要看更系统的课程和练习。混淆清理完成后，下一步就是处理过期卡密的判断。上一节我们让代码变得可读，本节我们来看看过期卡密怎样复活。


# 🔓 网络验证卡密软件逆向教程：第5章：过期卡密复活


上一章我们还原了简单的 VMP 混淆，本章来处理过期卡密复活。直播中在登录位置下断点，点击登录后程序断下来。程序先检测卡密长度，长度符合后再把卡密发送到服务器校验。这样做是为了避免把垃圾数据发送到服务器，减少不必要的服务器压力。

继续单步执行后，会看到一个跳转成立，跳转目标指向“卡号过期”。直播中点击回车跟过去，发现真正跳转到过期提示的位置是 0x419494，这是第一处关键位置。把这个跳转用 NOP 填充后，程序就不会再因为过期判断直接跳到过期提示。

```c
if (card_expired) {
    goto 卡密过期提示;
}
```

处理完第一处过期跳转后，继续跟踪代码，程序可能出现退出或闪退。这个现象说明还有第二层检测，也就是暗装。暗装会检测登录合法性，不合法就退出程序。因此过期卡密复活不是只改一个跳转就结束，还要继续处理合法性校验。

下面列出过期卡密复活的基本步骤，这些步骤对应直播中的演示流程。

- 使用正版过期卡密登录，确认程序提示卡密过期。
- 在登录判断位置下断点，点击登录触发断点。
- 单步执行，观察卡密长度校验是否通过。
- 找到跳转到“卡号过期”的关键跳转。
- 对关键跳转进行 NOP 填充。
- 继续单步跟踪，观察程序是否退出或闪退。
- 如果退出，进入暗装和合法性校验处理。

处理完过期跳转后，程序可能闪退，所以下一节要解决暗装。上一节我们让过期判断失效，本节我们来看看程序为什么还会退出。

# 🛡️ 网络验证卡密软件逆向教程：第6章：暗装与合法性校验处理


上一章我们处理了过期跳转，本章来解决暗装和合法性校验。直播中把过期跳转 NOP 后继续单步，执行到某一句时程序直接退出。这个退出不是普通的过期提示，而是程序在检测登录合法性，不合法就退出。直播中把这种检测称为暗装。

```c
if (!is_login_legal()) {
    ExitProcess();
}
```

![](img/8cfd39d5cc069cfbd3d93ef1cf8d6c08_9.png)

![](img/8cfd39d5cc069cfbd3d93ef1cf8d6c08_11.png)

处理暗装时，先找到第一次校验的位置，用 NOP 填充掉。然后继续往下找登录合法性校验函数。这个函数上面会有参数压栈，函数调用和参数属于一个整体，处理时要把这一块一起 NOP，不能只改一半。只改一半容易造成堆栈不平衡，程序会直接崩溃。

下面列出暗装处理的操作要点，这些要点能帮助初学者少走弯路。

- 找到程序退出前的合法性校验位置。
- 第一次校验位置用 NOP 填充。
- 找到合法性校验函数和它的参数压栈区域。
- 把函数调用和参数区域作为一个整体处理。
- 处理后点击登录，观察程序是否能正常进入。
- 如果崩溃，检查堆栈是否平衡。
- 复杂情况需要系统学习调试器断点和堆栈知识。

直播中完成这些处理后，过期卡密成功登录，说明过期判断和暗装都被绕过。这里再次提醒，NOP 填充要谨慎，堆栈不平衡会直接崩溃，相关细节需要结合系统课程练习。完成卡密部分后，下一节进入 QP 网络验证的反调试硬断绕过。上一节我们让过期卡密登录成功，本节我们来看看 QP 的硬断检测。

上一章我们处理了暗装，本章来分析 QP 网络验证的反调试硬断绕过。直播中提到 QP 是国内网络验证中很强的产品，作者综合能力很强，基于 VMP 3.X 泄露代码进行修改，能读懂 VMP 源码，也有很强的毅力。攻击方和防守方的角度不同，防守方要防很多层，攻击方只要找到一个突破点就能继续分析。

直播中先用 DBG 附加程序，出现错误弹窗，错误地址类似 `7FFE1FE46C0B`。这个弹窗不是调试器本身弹的，而是软件引用了无效内存导致错误。随后用 CE 测试，CE 打开进程正常，模块枚举和跳转地址都正常，但 CE 的调试器附加进程失败。说明程序对调试器附加做了处理，普通打开进程读数据可以，调试器附加会被拦截。

```text
DBG 附加 -> 错误弹窗，地址无效
```

直播中进一步查看钩子，发现程序对很多函数做了挂钩，其中 `RemoteBreak` 与断点有关。下断点会触发检测并崩溃，下硬件断点也会崩溃。挂钩位置示例为 `7FFE60E3CB60`，程序中多处都有 hook。处理方法是使用工具刷新检测进程，找到挂钩位置，鼠标右键恢复钩子，把断点相关检测干掉。

```text

恢复钩子 -> 可以正常查找访问和下硬件断点
```

# ✅ 网络验证卡密软件逆向教程：第9章：课程总结


![](img/8cfd39d5cc069cfbd3d93ef1cf8d6c08_53.png)

![](img/8cfd39d5cc069cfbd3d93ef1cf8d6c08_55.png)

![](img/8cfd39d5cc069cfbd3d93ef1cf8d6c08_57.png)

本课程中我们一起学习了网络验证卡密软件逆向的基础流程。开头先理解了卡密的长度和格式，知道正版过期卡密能帮助避开本地长度校验和服务器格式校验问题。然后定位登录校验函数，识别函数头和函数尾，在登录位置下断点，用单步执行观察 JMP 跳转。

接着我们学习了简单 VMP 混淆还原，核心做法是找到 JMP 目标地址，把无意义的垃圾区间填充为 NOP，NOP 字节是 0x90。混淆清理后代码变得可读，真正的业务逻辑开始出现。随后处理过期卡密复活，找到跳转到“卡号过期”的关键位置，用 NOP 让过期判断失效，再继续处理程序退出问题。

![](img/8cfd39d5cc069cfbd3d93ef1cf8d6c08_59.png)

暗装部分的核心是合法性校验，程序检测登录不合法就退出。处理时要把函数调用和参数区域作为一个整体 NOP，避免堆栈不平衡导致崩溃。最后学习了 QP 网络验证的硬断反调试，理解了 `RemoteBreak` 钩子、调试器附加失败、DBG 附加漏洞和恢复钩子的基本思路。

```text
完整流程：
卡密长度与格式 -> 登录校验定位 -> JMP垃圾指令NOP -> 过期跳转NOP -> 暗装合法性校验NOP -> QP硬断钩子恢复
```

![](img/8cfd39d5cc069cfbd3d93ef1cf8d6c08_61.png)

本课程的重点不是鼓励商业破解，而是通过简单案例理解逆向分析的基本方法。技术要用于合法合规的学习和研究，商业软件有版权和法律保护，不能用于侵害他人利益。掌握这些基础后，可以继续学习函数调用、堆栈平衡、调试器插件、更多反调试检测和系统化逆向课程。
