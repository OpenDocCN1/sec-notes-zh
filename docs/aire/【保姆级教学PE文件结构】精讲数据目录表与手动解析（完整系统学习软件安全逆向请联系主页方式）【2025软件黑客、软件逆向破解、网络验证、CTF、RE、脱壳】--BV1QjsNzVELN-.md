## PE文件结构精讲：14.1：回顾扩展PE头 🧱

上一节我们介绍了PE结构中的多个关键字段，本节先复习扩展PE头，为理解数据目录表的位置打基础。扩展PE头这个结构已经复习了很多遍。第一个成员`Magic`说明标志文件类型是32位还是64位；`AddressOfEntryPoint`说明程序的入口点。如果涉及壳之类的分析，都要看入口点。`ImageBase`表示程序默认载入的基址，程序映射到内存就从这里展开。`SectionAlignment`和`FileAlignment`分别是内存对齐和文件对齐。`SizeOfImage`说明内存中整个映像的总大小。`SizeOfHeaders`说明所有头的总大小，包括头、节表等内容。`CheckSum`表示校验，`Subsystem`表示子系统类型。今天我们要讲最后一项，也就是`NumberOfRvaAndSizes`，它表示数据目录表项的数量，数据目录表就在它下面，一般是16项，所以把16放到这里替换一下即可，也就是16个`IMAGE_DATA_DIRECTORY`。

以下是回顾扩展PE头时需要用到的核心字段说明，便于初学者把位置和含义对应起来。


```c
// 扩展PE头中的关键字段示意
Magic;              // 标志文件类型是32位还是64位
AddressOfEntryPoint;// 程序入口点，涉及壳分析时要重点看
ImageBase;          // 程序默认载入基址，内存映射从这里展开
SectionAlignment;   // 内存对齐
FileAlignment;      // 文件对齐
SizeOfImage;        // 内存中整个映像的总大小
SizeOfHeaders;      // 所有头的总大小
CheckSum;           // 校验
Subsystem;          // 子系统类型
NumberOfRvaAndSizes;// 数据目录表项数量，一般为16
```

## PE文件结构精讲：14.2：数据目录表概述 📚

刚才我们看到了扩展PE头中的`NumberOfRvaAndSizes`，本节来看看数据目录表本身。数据目录表位于扩展PE头结构的最后部分，本质上是一个结构体数组，每个元素叫`IMAGE_DATA_DIRECTORY`。在之前准备的PE结构图中有所展示，里面包含各种信息。逆向安全分析、壳、脱壳、木马分析中，数据目录表几乎是入口级别的分析重点，说明它的地位非常高。

下面是数据目录表在PE头中的位置关系，核心概念可以用公式描述为：`PE头 -> 扩展PE头 -> 数据目录表`。

```text
PE头
  └─ 扩展PE头
       └─ 数据目录表（IMAGE_DATA_DIRECTORY数组）
```

## PE文件结构精讲：14.3：数据目录结构定义 🧩

上一节我们介绍了数据目录表是结构体数组，本节来看看每个数组元素的结构定义。`IMAGE_DATA_DIRECTORY`这个结构有两个成员。第一个成员`VirtualAddress`表示该表或数据块在内存映像中的RVA，也就是相对虚拟地址。第二个成员`Size`表示该表或数据的大小，以字节为单位。也就是说，数据目录项只保存RVA和Size，真正的数据在哪里呢？通常在节里。数据目录等于指针，指针就是内存地址，它只是指向那个内容，而真正的内容在对应的节里边。这些节才是承载这些数据的容器。我们再看一眼，它里边真的只有RVA和数据大小，所以这个RVA只是指向了某个节的内存地址，然后我们再手动去找这个Size的数据大小。

以下是数据目录结构的定义，核心概念用代码描述如下。

```c
typedef struct _IMAGE_DATA_DIRECTORY {
    DWORD VirtualAddress; // 数据或表的RVA，相对虚拟地址
    DWORD Size;           // 数据或表的大小，单位字节
} IMAGE_DATA_DIRECTORY;
```

## PE文件结构精讲：14.4：数据目录数量与指针本质 🔢

上一节我们明确了数据目录项只保存RVA和Size，本节来看看数据目录的数量以及“指针”的本质。数据目录的数量由扩展PE头中的`NumberOfRvaAndSizes`成员定义，一般是16。微软官方原话是这样的：目录不是固定的，具体要看这个成员，但是一般来说有16个。每个目录项占8个字节，因为RVA和Size都是4个字节，4字节加4字节总共8字节，16项总共128个字节。我们还要知道，数据目录表本身是一个表格，只保存RVA和Size，真正的数据通常在节里。也就是说，数据目录等于指针，指针就是内存地址，它只是指向那个内容，而真正的内容在对应的节里边。这些节才是承载这些数据的容器。数据目录项里的RVA只是指向了某个节的内存地址，然后我们再手动去找这个Size的数据大小。

以下是数量计算的核心公式，方便初学者记住128字节的来源。

```text
数据目录项数量 = NumberOfRvaAndSizes
一般数量 = 16
每个目录项大小 = sizeof(DWORD) + sizeof(DWORD) = 4 + 4 = 8字节
数据目录表总大小 = 16 * 8 = 128字节
```


> 微软官方原话：目录不是固定的，具体要看`NumberOfRvaAndSizes`成员，但是一般来说有16个。

## PE文件结构精讲：14.5：覆盖区与加壳等非通常情况 🧪

上一节我们说到真正数据通常在节里，本节来看看“通常之外”的例外情况。当然有例外，这些都属于非正常的程序。一种情况是overlay覆盖区，在可执行文件的末尾可能会有一些附加数据。这些数据不属于任何节，但是仍可能包含一些有效信息。数据目录一般不会指向这里，但是一些异常或者恶意样本有可能把表格放到覆盖区里面，导致常规的映像方式找不到。覆盖区可以演示：在工具里点击编辑，点击插入，点击插入字节，在文件末尾处插入8个字节，末尾是A00也就是2560的位置插入8个字节，然后把最后的8个字节改成“小迪”，保存这个文件。插入保存之后不影响程序运行，所以可以放任何有意数据在这里。大家要知道，插入的数据不属于任何节，所以不会被PE加载器当作映像的一部分映射到进程虚拟内存，运行起来之后不会出现在进程模块的内存映像中，它只存在于本地。如果程序运行起来想要访问这个附加数据，必须自己从磁盘去读取。如果希望附加数据随模块一起映射到内存，就应该把这个数据放到一个节里，可以新增节或者扩展某个节，这两个做法后边会讲到，放进去之后再去修正头部的Size，这里先简单了解即可。第二种情况是加壳或者运行时解密，这种情况也可以先简单了解，大家先自己看一下，距离它还比较远。

以下是覆盖区实验的示意代码，核心概念用代码描述如下。

```text
文件末尾位置 = A00（即2560）
插入字节数 = 8
插入后末尾8字节内容 = “小迪”
保存文件
结论：覆盖区数据不属于任何节
     不会被PE加载器映射到进程虚拟内存
     只存在于本地文件
     程序若要访问，需要自己从磁盘读取
```

## PE文件结构精讲：14.7：手动解析数据目录 🔍

上一节我们列出了16个数据目录项，本节来做手动解析数据目录的实验。现在我们知道每个目录项的`VirtualAddress`是一个RVA，是一个相对虚拟地址，是一个内存地址。如果要查看它的数据，有两个方法：一个方法是定位到文件中的实际偏移去查看；第二个方法是让程序运行起来，用DB附加去分析，这种没有什么难度。所以我们选择第一个方法做实验。如何定位到文件中的实际偏移？首先通过节表找到该RVA所在的节，然后计算文件偏移。之前讲过公式：文件偏移等于RVA减去当前节的起始内存地址，再加上当前节的文件起始地址。

以下是手动解析时使用的核心公式，建议初学者反复对照节表计算。

```text
文件偏移 = RVA - 当前节起始内存地址 + 当前节文件起始地址
```

实例一是空数据情况。现在看到的是数据目录表中的export导出表。如果某个数据目录项的RVA以及Size为0，说明该表无数据，也没有相对的功能。可以看到export两个都是0，所以它没有相关数据，这种就不需要再看了。一个程序到底有哪些数据目录项？可以看右边，如果右边有东西，说明这个程序存在该数据目录项。接下来看第二个import实例，解析import也就是导入表。导入表的`VirtualAddress`是2010，大小是3C。2010这个地址落在RDATA一个空间，看到`VirtualAddress`是2000，大小是922，2010落在2000到2000+922这个区间。所以内存偏移就是2010减去2000等于10。然后计算文件偏移，文件偏移看谁？以`PointerToRawData`为基础，它是600，所以文件偏移就是600加上这个10的偏移等于610。导入表大小是3C，把程序运行起来，跳转到2010选中对应3C字节，然后在本地文件中找到刚才计算的610，选中对应3C字节。可以看到这个数据一模一样，说明计算正确。

以下是import导入表手动解析的核心计算过程，便于逐步核对。

```text
导入表 VirtualAddress = 2010
导入表 Size = 3C
所在节起始内存地址 = 2000
所在节大小 = 922
内存偏移 = 2010 - 2000 = 10
节文件起始地址 PointerToRawData = 600
文件偏移 = 600 + 10 = 610
运行程序跳转到 RVA 2010，选中 3C 字节
本地文件定位到偏移 610，选中 3C 字节
比对结果：数据一致
```
