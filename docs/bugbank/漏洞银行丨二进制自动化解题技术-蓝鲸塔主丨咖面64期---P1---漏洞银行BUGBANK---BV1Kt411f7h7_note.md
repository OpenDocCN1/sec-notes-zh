## 第一部分：符号执行基础

上一节我们概述了课程目标，本节中我们来看看什么是符号执行，以及它如何成为自动化解题的基石。

符号执行是一种程序分析技术。其核心思想是：**使用符号（即未知变量，如 `x`）代替程序输入的具体值，让程序在符号状态下执行，并收集执行路径上的所有约束条件，最后通过求解这些约束来得到能使程序到达目标状态的具体输入值。**

### 符号执行过程示例
考虑一个简单的程序流程：
1.  程序要求输入一个值 `x`。
2.  如果 `x >= 5`，则执行路径 A；否则执行路径 B。
3.  在路径 A 中，如果 `x < 50`，则到达目标（成功）；否则失败。

![](img/680ae1ed515966b15d367bd1a71209f2_7.png)

传统动态分析需要输入一个具体值（如 `10`）来测试一条路径。而符号执行则：
*   将输入设置为符号 `x`。
*   同时探索路径 A 和路径 B。
*   对于路径 A，收集约束条件：`x >= 5` 且 `x < 50`。
*   求解器（如 Z3）会找到一个满足该约束的具体值（例如 `20`），这个值就是能使程序到达目标的有效输入。

**公式化描述**： 符号执行旨在求解满足路径约束 **φ(path)** 的输入变量 **x** 的值，使得程序能到达目标状态 **target_state**。即求解 **∃x: φ(path(x)) ∧ (state(x) == target_state)**。

这种方法可以避免手动逆向复杂算法，自动遍历所有可能的路径并找到通关条件。

## 第二部分：静态分析与动态分析简介

在深入自动化工具之前，我们先简要回顾传统分析方法，以理解自动化工具的优势。

以下是常用的二进制分析工具和方法：

![](img/680ae1ed515966b15d367bd1a71209f2_9.png)

![](img/680ae1ed515966b15d367bd1a71209f2_11.png)

*   **`file` 命令**： 查看文件类型、架构（如 32/64 位）。
*   **`strings` 命令**： 提取文件中所有可打印字符串，有时能直接发现 Flag。
*   **`ltrace` / `strace` 命令**： 跟踪程序调用的库函数或系统调用。
*   **静态分析工具 (IDA Pro, Ghidra)**： 反汇编程序，查看控制流图，将汇编代码转换为更易读的伪代码。
*   **动态调试工具 (GDB, OllyDbg)**： 运行程序，逐步执行，实时查看和修改寄存器、内存值。

![](img/680ae1ed515966b15d367bd1a71209f2_13.png)

![](img/680ae1ed515966b15d367bd1a71209f2_15.png)

### 方法对比
*   **静态分析**：
    *   *优点*： 可以查看全部代码，发现所有执行路径。
    *   *缺点*： 难以理解程序动态交互逻辑，入口点可能难以定位。
*   **动态分析**：
    *   *优点*： 可以观察程序运行时状态，交互清晰。
    *   *缺点*： 一次运行只能覆盖一条路径，路径爆炸时难以穷尽；可能触发反调试机制。

Angr 是一个基于 Python 的二进制分析平台，它集成了符号执行、控制流分析、漏洞挖掘等功能，支持多种架构。

### 实战 1：Angr 基础破解
我们以一个简单的 CTF 逆向题 `r100` 为例。程序会要求输入一个密码。

![](img/680ae1ed515966b15d367bd1a71209f2_35.png)

![](img/680ae1ed515966b15d367bd1a71209f2_37.png)

**解题思路**：
1.  用 IDA 等工具找到程序输出成功信息（如 `"Nice!"`）和失败信息（如 `"Incorrect password"`）的地址。
2.  编写 Angr 脚本，让其从程序入口开始符号执行，探索路径。
3.  设定目标地址为成功地址，避免地址为失败地址。
4.  让 Angr 自动求解出能到达成功地址的输入。

![](img/680ae1ed515966b15d367bd1a71209f2_41.png)

**核心代码模板**：

![](img/680ae1ed515966b15d367bd1a71209f2_47.png)

![](img/680ae1ed515966b15d367bd1a71209f2_49.png)


![](img/680ae1ed515966b15d367bd1a71209f2_51.png)

![](img/680ae1ed515966b15d367bd1a71209f2_53.png)

![](img/680ae1ed515966b15d367bd1a71209f2_55.png)

![](img/680ae1ed515966b15d367bd1a71209f2_57.png)


![](img/680ae1ed515966b15d367bd1a71209f2_59.png)

![](img/680ae1ed515966b15d367bd1a71209f2_61.png)

![](img/680ae1ed515966b15d367bd1a71209f2_63.png)

![](img/680ae1ed515966b15d367bd1a71209f2_65.png)


![](img/680ae1ed515966b15d367bd1a71209f2_67.png)

```python
import angr
# 加载二进制文件，不自动加载依赖库（适用于大部分CTF题）
proj = angr.Project('./r100', auto_load_libs=False)
# 创建初始状态（从程序入口开始）
state = proj.factory.entry_state()
# 创建模拟管理器，用于路径探索
simgr = proj.factory.simulation_manager(state)
# 指定目标地址和避免的地址（需通过IDA分析获得）
find_addr = 0x400844  # 例如 "Nice!" 的地址
avoid_addr = 0x400855 # 例如 "Incorrect password" 的地址

# 开始探索，寻找通向 find_addr 的路径，避开 avoid_addr
simgr.explore(find=find_addr, avoid=avoid_addr)
# 打印找到的解决方案（即正确输入）
if simgr.found:
    solution_state = simgr.found[0]
    # 假设输入是从标准读取的，并存储在特定的位置，这里打印标准输入的内容
    print(solution_state.posix.dumps(0))  # dumps(0) 表示标准输入
else:
    print("No solution found")
```
运行脚本后，Angr 会输出求解出的字符串，例如 `b'Code_Talkers'`，这就是正确的密码。

```python
import angr
import claripy  # Angr 的约束求解模块，用于创建符号

proj = angr.Project('./ais3_crackme', auto_load_libs=False)
# 创建一个长度为 50*8 比特的符号向量，代表命令行参数（字符串）
# BVS 表示 BitVector Symbol
arg1 = claripy.BVS('arg1', 50 * 8)
# 创建初始状态，并设置参数：第一个是程序名，第二个是我们的符号参数
state = proj.factory.entry_state(args=['./ais3_crackme', arg1])
simgr = proj.factory.simulation_manager(state)
# 通过IDA分析找到成功和失败地址
find_addr = 0x400602  # "Correct" 地址
avoid_addr = 0x4005F7 # "I'm sorry" 地址
simgr.explore(find=find_addr, avoid=avoid_addr)

if simgr.found:
    solution_state = simgr.found[0]
    # 获取符号参数 arg1 的求解结果，并转换为字符串
    solved_arg1 = solution_state.solver.eval(arg1, cast_to=bytes)
    print(solved_arg1.rstrip(b'\x00'))  # 去除末尾的填充空字符
else:
    print("No solution found")
```
运行脚本后，将得到正确的密钥，格式可能为 `b'flag{...}'`。

## 第五部分：使用 Z3 求解器处理复杂约束

![](img/680ae1ed515966b15d367bd1a71209f2_113.png)

![](img/680ae1ed515966b15d367bd1a71209f2_115.png)

![](img/680ae1ed515966b15d367bd1a71209f2_117.png)

Angr 适合处理完整的、路径清晰的程序。但当面对纯算法、代码片段或路径爆炸（如大量随机数分支）的问题时，更底层的 **Z3** 求解器可能更高效。Z3 是微软开发的高性能定理证明器，Angr 的约束求解后端就是 Z3。

![](img/680ae1ed515966b15d367bd1a71209f2_119.png)

### Z3 基础
Z3 可以直接求解方程组和逻辑约束。例如，求解：
*   `x + y == 6`
*   `2*x == 3*y + 6`

**Z3 求解代码**：

![](img/680ae1ed515966b15d367bd1a71209f2_121.png)

![](img/680ae1ed515966b15d367bd1a71209f2_123.png)

```python
from z3 import *

# 定义变量
x = Real('x')
y = Real('y')

# 创建求解器
s = Solver()
# 添加约束条件
s.add(x + y == 6)
s.add(2*x == 3*y + 6)

# 检查是否有解
if s.check() == sat:  # sat 表示可满足（有解）
    m = s.model()     # 获取模型（解）
    print(f"x = {m[x]}")
    print(f"y = {m[y]}")
else:
    print("无解")
```
运行后将输出 `x = 24/5`, `y = 6/5`。

### Z3 支持的数据类型和操作
*   **常用类型**： `BitVec('a', 32)` (32位位向量，类似 int), `Real('x')` (实数), `Bool('p')` (布尔值)。
*   **运算**： 标准算术和逻辑运算 (`+, -, *, /, &, |, ^, ==, !=, <, >` 等)。
*   **无符号数比较**： 对于无符号位向量，需使用 `ULT` (无符号小于), `ULE` (无符号小于等于) 等专用操作。

### 实战 2：使用 Z3 逆向算法
假设有一段 C 代码验证函数，其核心是复杂的算术和逻辑运算。我们可以将运算过程用 Z3 的语法重写，将输入设为符号变量，让 Z3 求解出满足最终验证条件的输入值。

![](img/680ae1ed515966b15d367bd1a71209f2_125.png)

![](img/680ae1ed515966b15d367bd1a71209f2_127.png)

**通用解题模板**：
```python
from z3 import *

# 定义输入符号变量，例如一个 32 位的数（可能代表4个字符）
inp = BitVec('inp', 32)

s = Solver()

# 根据逆向出的算法，添加约束条件
# 例如： (inp * 0x12345678) & 0xFFFF == 0xABCD
s.add((inp * 0x12345678) & 0xFFFF == 0xABCD)

# 可以添加额外约束，如输入是可打印字符
for i in range(4):
    byte = Extract(8*i+7, 8*i, inp)  # 提取第 i 个字节
    s.add(byte >= 0x20, byte <= 0x7E) # 可打印 ASCII 范围

if s.check() == sat:
    m = s.model()
    solved_inp = m[inp].as_long()
    # 将整数转换为字节字符串（注意大小端）
    flag = solved_inp.to_bytes(4, 'little')
    print(f"Found input: {flag}")
else:
    print("No solution")
```

## 第六部分：综合实战——复杂随机数问题

![](img/680ae1ed515966b15d367bd1a71209f2_135.png)

![](img/680ae1ed515966b15d367bd1a71209f2_137.png)

有些题目结合了随机数，使得路径数剧增，Angr 直接探索效率低下。这时需要结合静态分析、动态调试与 Z3 求解。

**解题思路（以某 CTF 题为例）**：
1.  **静态分析 (IDA)**： 定位程序主要验证逻辑，发现其使用 `srand(seed)` 初始化随机数，`seed` 由用户输入的第一部分计算得出。后续验证使用 `rand()` 生成多个值参与运算。
2.  **第一部分求解**： 由于 `seed` 的计算是确定的（无随机数），可以使用 **SymPy**（符号数学库）或 **Z3** 直接求解出能产生正确 `seed` 的输入第一部分。
3.  **动态调试获取随机序列**： 因为 `srand(seed)` 固定后，`rand()` 序列是固定的。使用调试器（如 GDB 配合 IDA）运行程序，在输入第一部分后，设置 `seed` 为我们求解出的值，然后步进程序，从内存中提取出后续 `rand()` 生成的所有确定值。
4.  **第二部分求解**： 将提取出的随机数作为已知常量，代入到第二阶段的验证算法中。再次使用 **Z3**，将用户输入的第二部分设为符号变量，建立方程并求解。
5.  **组合输入**： 将第一部分和第二部分求解结果合并，即为完整 Flag。

这种方法避免了 Angr 在无数随机分支中挣扎，通过“分而治之”和动态调试获取关键中间状态，大大提升了求解效率。
