# SSL/TLS握手过程

+   - 客户端把它所支持的算法列表和一个用于帮助产生对话密钥的随机数发送给服务器。
+   - 服务器从表中选择一种支持的算法，再产生一个用于帮助产生对话密钥的随机数，然后把它们同自己的证书一起发送给客户端。
+   - 客户端对服务器证书进行认证，再产生一个随机密码串 pre_master_secret，并以服务器证书中的私钥将其加密。这是握手过程中最重要的一步。将来所有通信数据的安全都依赖于 pre_master_secret 的安全性。此处使用 RSA 或 DH，处理细节会稍有不同。
+   - 双方根据 pre_master_secret 和客户端、服务器的随机数独立计算加密密钥和 MAC 密钥。
+   - 双方将各自所有握手消息的 MAC 值发给对方。防止有重放攻击的可能。
