
## 6.2 SSL/TLS协议

- SSL(Secure Socket Layer,安全套接层)/TLS(Transport Layer Security,传输层安全)是一种在两台机器之间提供安全通道的协议，主要功能是提供网络上可信赖的通信服务，让通信双方在通过网络传输信息时，能够保障数据的完整性及保密性。安全通道的主要特点是透明性，即除完成加密功能外，它对传输数据不做任何改动，一端写入的数据完全是另一端读取的内容。这种透明性使得几乎所有基于TCP的协议稍加改动就可以在SSL/TLS上运行，非常方便。

- SSL/TLS的多个版本中，SSL版本1（SSLv1）从未广泛应用过，SSL版本2（SSLv2）和SSL版本3（SSLv3）几乎是完全不同的两个版本，而TLS和SSLv3则极为相似。由于SSLv2已经过时，下面讨论的是关于SSLv3/TLS的内容。

## SSL/TLS握手过程

- 客户端把它所支持的算法列表和一个用于帮助产生对话密钥的随机数发送给服务器。
- 服务器从表中选择一种支持的算法，再产生一个用于帮助产生对话密钥的随机数，然后把它们同自己的证书一起发送给客户端。
- 客户端对服务器证书进行认证，再产生一个随机密码串 pre_master_secret，并以服务器证书中的私钥将其加密。这是握手过程中最重要的一步。将来所有通信数据的安全都依赖于 pre_master_secret 的安全性。此处使用 RSA 或 DH，处理细节会稍有不同。
- 双方根据 pre_master_secret 和客户端、服务器的随机数独立计算加密密钥和 MAC 密钥。
- 双方将各自所有握手消息的 MAC 值发给对方。防止有重放攻击的可能。

## SSL/TLS数据传输

经过握手之后，即开始了第二个阶段：数据传输。在前一阶段握手协商的加密密钥在这一阶段中用来加密数据，实现数据的安全传输。这一阶段主要使用纪录协议来实现。

## 6.3 IPSec

- SSL/TLS可以提供应用层的安全通信，但是它需要应用软件修改自身代码，利用SSL/TLS API来实现这种通信安全，从而带来了额外的开销。而IPSec则无需应用软件进行任何修改，就可以在一定程度上获得安全保护。
- 我们知道IPv4本身几乎没有安全性的保障，唯一的一个安全选项也仅仅是当时为军方专门预留的，而当前的各种IP实现中都没有处理这一选项。IPv4的安全问题很多，攻击者可以轻易地伪造IP包中的地址，或者篡改通信内容，或者拦截、查看、重放包的内容等。当接收方收到IP包时，他既无法保证传输数据内容没有泄露，也无法保证传输数据在途中没有被篡改，他甚至无法肯定数据是否真是源自IP报文中的源地址。

## IPSec 功能

IPSec有效地提供了针对以上问题的对策，保护了IP数据报的安全服务：

- 访问控制：利用数据加密，防止非授权访问。
- 数据来源认证：利用数字签名功能，验证发送方的真实身份。
- 无连接完整性：利用数字签名功能，防止传输数据被恶意篡改。
- 数据内容的保密性：利用数据加密功能，防止传输数据内容被非法读取。
- 抗重放攻击：利用唯一的传输序列号和数字签名，防止传输数据被恶意地重新发送。
- 有限的传输流量保密性：利用加密保护原始IP报文头的功能，可以降低流量分析攻击的效果。

IPSec在IP层上提供这种标准的的安全服务，为IP及上层协议提供安全保证。它可以上保障主机之间、网络安全网关（如路由器或防火墙）之间、主机与安全网关之间的数据报的安全。也就是说，IPSec可以在主机上实现，也可以在网关上实现。

## IPSec实现

IPSec用两类安全传输协议来提供安全服务：AH（Authentication Header，认证头部）和ESP（Encapsulating Security Payload，封装安全负载）。其中，AH可实现访问控制、证明数据来源、保障数据完整性以及防止重放攻击。ESP则可以更进一步，保障数据的保密性，并为数据流提供限制的保密性保障。同SSL/TLS的握手协议类似，这两种传输协议同样需要进行协商安全协议、密码算法和密钥等安全参数，这部分工作由一类密钥管理协议（Internet Key Exchange，IKE）来完成。

IPSec使用的密钥既可用于某一种对称加密算法（提供数据的保密性服务时），也可用于经密钥处理过的MAC（提供数据的完整性服务时）。为保证通信的通畅，IPSec的运算速度应该足够快，而公钥算法（如RSA或DSS）的速度都不能满足这一要求。

AH和ESP可以支持两种不同的工作模式：传输模式和隧道模式。前者是对上层协议进行安全保护，如TCP、UDP、ICMP的数据包。后者对整个IP数据报进行安全保护，这时需要为受AH或ESP保护的IP数据报添加一个新的IP头部，这样原IP数据报就变成了新报文的负载信息。当通信的两端至少有一端是安全网关时，需要使用隧道模式来实现安全通信。

## 两种工作模式比较

两种工作模式各有利弊。一般而言，隧道模式的安全性更好一些。由于IP报文被完全封装，攻击者无法通过分析网络流量来分析信息内容。有些应用场合，使用隧道模式也非常方便。比如当两个局域网进行安全通信时，只需在双方边界上的路由器上使用IPSec的隧道模式提供安全服务，就可以为网内未安装IPSec的主机提供网间的安全通信了。传输模式的优势则在于为实现安全服务而增加的报文长度相对较少，占用的带宽相对较少，而且还可以支持服务质量（QoS）的服务要求。

## 安全关联（Security Association，SA）

- 安全关联是IPSec的基础。用IPSec来为IP数据报提供安全服务前，必须首先建立一个安全关联。它包含通信双方所协商的一些安全信息，包括协议类型、工作模式、密码算法等。
- 安全关联是安全通信两端间的一种单向的关系。一个对等关系需要两个安全关联。安全关联可用于AH或ESP，但不可同时用于两者。一个对等关系上同时使用AH和ESP时，需要4个安全关联。
- 安全关联通常用一个三元组来唯一标识：<安全参数索引，IP目的地址，安全协议>。安全参数索引是一个32位的整数，用于标识不同的SA。IP目的地址是指安全关联的目的端的地址。安全协议指明该关联用于AH还是ESP。IPSec中专门有安全关联数据库（SADB）来维护SA的信息。
- 此外，IPSec还维护一个安全策略数据库（SPD）。它由一些策略条目组成，每条记录定义了一种安全策略。策略规定了对数据报的三种可能的处理方法：应用、丢弃和绕过。
- 安全策略数据库和安全关联数据库需要共同使用。对于进入或离开的每个IP报文，都要在安全策略数据库中检索可能的安全应用，而检索结果又可能指向一个或多个SA。这样，在安全策略的指导下，将SA中相应的安全参数信息应用到IP报文上。

## 认证首部（AH）

认证首部各字段含义如下：

- 下一首部（8位）：标识认证数据后负载的类型。例如TCP、UDP或ICMP等。
- 负载长度（8位）：AH长度（以32位为单位）减去2。
- 保留（16位）：保留将来使用。目前暂置为0。
- 安全参数索引（32位）：标识安全关联。
- 序列号（32位）：单调递增的计数器的值。用于防范重放攻击。
- 认证数据（变长）：长度必须是32位的整数倍。用于完整性检查和认证发送源的数据。
