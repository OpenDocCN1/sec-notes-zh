# FIFO或命名管道

管道是一个强大的进程间通信机制，但它也有一些缺点。
首先，管道只能用来连接具有亲属关系的进程，例如一个父进程与其子进程。当用户试图开发一个真正的服务器程序、永远运行下去以提供系统范围服务的时候，就不能使用管道。理想的情况是，顾客进程应该能够以一种与服务器进程无关的方式存在，并且通过管道与之交互，完成任务后再离开服务进程。这一点无法通过传统的管道来完成。
其次，管道不能是永久的。它必须在每次需要的时候被创建，并且在访问它的进程终止后被销毁。

为了解决这些问题，可以使用一种不同的管道。这种进程间通信机制称为FIFO或者命名管道。包括涉及到read和write在内的操作，FIFO和管道是等同的，它在进程之间作为一个先入先出的通信渠道。事实上，特别在内核级，FIFO和管道共享了大量的公共代码。但与管道不同的是，FIFO是一个持久的设备，并被赋予了一个UNIX文件名。FIFO也有所有者、大小以及与之关联的访问权限。它可以象其它所有的UNIX文件那样被打开、关闭和删除，但是在读写时显示出了与管道相同的属性。
