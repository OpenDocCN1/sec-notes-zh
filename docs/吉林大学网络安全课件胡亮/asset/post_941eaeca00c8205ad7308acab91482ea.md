## 第2章 进程通信

在计算机网络中，通信的两个进程可能处于同一个物理节点上，也可能分别处于两个不同的物理节点上。对于一个物理节点上不同进程之间的通信，绝大多数操作系统提供了管道、共享内存、消息队列方法。对于处于两个不同的物理节点上的进程，要想通过通信网络实现进程通信，必须规定一套通信协议。从硬件连接到实现进程通信，一般要经过四个层次，就是物理层、数据链路层、网络层，最后是传输层。计算机网络向用户提供的各种服务，都是建立在进程通信的基础上。

### 2.1 同一节点上的进程间通信

大多数UNIX系统提供多种进程通信方式，主要有信号（Signal）、管道（pipe）、命名管道（FIFO）、消息队列（message queue）、信号灯（semaphore）、共享内存（shared memory）和内存映象（memory mapped file）等。

## FIFO或命名管道

管道是一个强大的进程间通信机制，但它也有一些缺点。
首先，管道只能用来连接具有亲属关系的进程，例如一个父进程与其子进程。当用户试图开发一个真正的服务器程序、永远运行下去以提供系统范围服务的时候，就不能使用管道。理想的情况是，顾客进程应该能够以一种与服务器进程无关的方式存在，并且通过管道与之交互，完成任务后再离开服务进程。这一点无法通过传统的管道来完成。
其次，管道不能是永久的。它必须在每次需要的时候被创建，并且在访问它的进程终止后被销毁。

为了解决这些问题，可以使用一种不同的管道。这种进程间通信机制称为FIFO或者命名管道。包括涉及到read和write在内的操作，FIFO和管道是等同的，它在进程之间作为一个先入先出的通信渠道。事实上，特别在内核级，FIFO和管道共享了大量的公共代码。但与管道不同的是，FIFO是一个持久的设备，并被赋予了一个UNIX文件名。FIFO也有所有者、大小以及与之关联的访问权限。它可以象其它所有的UNIX文件那样被打开、关闭和删除，但是在读写时显示出了与管道相同的属性。

## FIFO使用

在大多数情况下，对FIFO进行程序设计与对普通管道进行编程基本相同。唯一明显的差别在初始化部分。与使用pipe不同的是，一个FIFO通过mkfifo来创建。在较早的UNIX版本中，可能需要使用一个更通用的调用mknod。具体使用方法如下：

```
#include <sys/types.h>
#include <sys/stat.h>
int mkfifo(const char *pathname, mode_t mode);
```

系统调用mkfifo可以创建一个FIFO文件。第一个参数pathname指定它的名字，mode给出了FIFO的权限。

一旦FIFO创建完成，必须使用open打开它。下面程序段说明了它的使用：

```
#include <sys/types.h>
#include <sys/stat.h>
#include <fcntl.h>
...
Mkfifo("/tmp/fifo", 0666);
...
fd=open("/tmp/fifo", O_WRONLY);
```

open将一直阻塞直到另一个进程打开这个FIFO来读取数据（当然，如果这个FIFO已经被打开读取了，open调用将立即返回）。

对一个FIFO可以进行非阻塞打开调用。为了达到这一点，open调用必须通过把O_NONBLOCK标志与O_RDONLY或者O_WRONLY联会使用来完成。具体如下：

```
if((fd = open("/tmp/fifo", O_WRONLY| O_NONBLOCK))== -1)
perror("open fail");
```

如果没有进程打开FIFO来读取，则open将返回-1而不是阻塞，并且errno将包含错误码ENXIO。相反，如果open调用成功了，则将来对该FIFO的write调用也是非阻塞的。

## 消息队列

消息队列是一个消息的链接列表，消息都保存在内核中。如果把一个消息添加到一个队列，队列显示出FIFO的特性，因为新消息被添加到队列的末尾。但是和FIFO管道不同，队列中的消息能够以随意的顺序进行检索，因为可以通过消息的类型把消息从队列中检索出来。

## 创建和打开消息队列

- msgget()创建一个新队列或者打开一个已有的队列。其调用形式如下：
- #include <sys/types.h>
- #include <sys/ipc.h>
- #include <sys/msg.h>
- int msgget(key_t key, int flags);

- key是所创建队列或打开队列的键值，如果成功则返回消息队列的ID，如果调用失败，则返回值为-1，设置出错变量errno的值。如果errno等于EACCESS，说明拒绝访问；如果errno等于EEXIST，说明队列存在，不能创建；如果errno等于EIDRM，说明队列已经被标记为删除；如果errno等于ENOENT，说明队列不存在；如果errno等于ENOMEM，说明没有足够的内存创建队列；如果errno等于ENOSPC，说明超出最大队列限制

- 系统函数msgget的第一个参数key将会与其他已经存在于内核中的键值比较。这时，打开和存取操作是和参数flags中的内容相关的。

- 如果flags是IPC_CREAT，内核中没有键值key所对应的队列，则创建它。

- 如果在flags中同时使用IPC_CREAT和IPC_EXCL，内核中已经有键值key所对应的队列，则失败。IPC_EXCL不能单独使用。

- 如果单独使用IPC_CREAT，则msgget()要么返回一个新创建的消息队列的ID，要么返回具有相同键值key的消息队列的ID。

## 向队列中写入消息

- 要把一个新消息添加到队列的末尾，可以使用msgsnd函数，它原型如下：

```
#include <sys/types.h>
#include <sys/ipc.h>
#include <sys/msg.h>
int msgsnd(int msqid, struct msgbuf *msgp, int msgsz, int msgflag);
```

- 如果msgsnd()执行成功则返回0，但如果失败则返回-1并且设置全局出错变量errno。参数msqid必须是前面调用msgget返回的队列ID。msgsz是所添加消息的字节数，但不包含消息类型的长度。msgp是一个指向消息的指针。消息由msgbuf结构表示，这个结构由消息类型和组成消息的数据字节所构成。参数msgflag可以设置为0，此时该参数被忽略，或者设置为IPC_NOWAIT，如果消息队列已满，那么此消息则不会被写入到消息队列中，控制将返回到调用进程中。如果没有指明，调用进程将会挂起，直到消息可以写入到队列中。

## 读取队列中的消息

- 要从队列中取出一个消息，可以使用msgrcv，它的语法如下：
  ```c
  #include <sys/types.h>
  #include <sys/ipc.h>
  #include <sys/msg.h>
  int msgrcv(int msqid, struct msgbuf *msgp, int msgsz, long mtype, int msgflag);
  ```

- 如果调用成功，则返回复制到消息缓冲区中的字节数；如果失败，则返回-1。第一个参数用来指定将要读取消息的队列。第三个参数代表要存储消息的消息缓冲区的地址。第三个参数是消息缓冲区的长度，不包括mtype的长度。第四个参数是要从消息队列中读取的消息的类型。如果此参数的值为0，那么队列中最长时间的一条消息将返回，而不论其类型是什么。第五个参数如果是IPC_NOWAIT，那么当没有消息可以使用时，调用将把ENOMSG返回到调用进程中。否则，调用进程将会挂起，直到队列中有一条消息满足msgrcv函数的参数要求。

## 删除消息队列

msgctl函数提供了对消息队列在一定程度上的控制功能，它的原型如下：

```
#include <sys/types.h>
#include <sys/ipc.h>
#include <sys/msg.h>
int msgctl(int msqid, int cmd, struct msqid_ds *buf);
```

一般而言，msqid是一个已经存在的队列的ID。cmd可以为如下值之一：

- ① IPC_RMID，删除队列msqid。
- ② IPC_STAT，用队列的msqid_ds结构填充buf，并让你查看队列的内容而不会删除任何消息。因为这是一种非破坏性的读操作，可以认为它和msgrcv类似。
- ③ IPC_SET，让你改变队列的UID、GID、访问模式和队列的最大字节数。
