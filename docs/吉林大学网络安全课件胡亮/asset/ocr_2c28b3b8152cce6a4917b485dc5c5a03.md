# 组通信的设计问题

组成员的管理。当需要进行组通信的时候，需要某种方法建立和删除一个组。同时需要提供一种方法允许一个进程加入到某个进程组或者离开某个进程组。组成员的管理有两种常见的管理方式：第一种是集中式的管理方式，第二种是分布式的管理方式。在集中式的管理方式中，设置一个组管理服务，任何管理请求都发向这个服务，组管理服务员为所有进程组及其组成员设置一个数据库。集中式的管理方式比较直接、高效和易于实现。同样所有的集中式机构一样它存在着单点失效的问题。如果组管理服务员失效，组管理机制不再存在，可能导致大部分或所有进程组需要重构。在分布式的管理方式中不存在一个集中的组管理服务。当一个外部进程打开一个进程组的时候，它需要向组中的所有成员发送一个报文，关于它要加入进程组同时如此。当一个进程要加入一个进程组时，需要向组中的所有成员发送一个加入报文，当离开一个进程组时需要向组中的所有成员发送一个离开报文。

无论采用那种管理方式，存在着如下需要解决的问题：首先，如果一个组成员崩溃，它实际上离开了所在的进程组，但是它并没有声称，在这种情况下，组管理服务员却没有它的成员认为这还是这种情况。在实际的情况中，如果组中的其他成员发现它负责任务没有完成，就认为该成员已经脱离该组，可以将其从进程组中删除。第二个问题是，加入和离开一个组必须和要发送的报文同步。也就是说，从一个进程加入一个进程组那一刻起，所有发送到该组的报文，该进程必须接收。同样，当一个进程离开一个进程组之后，它再也不能接收任何发送到该组的报文。第三个问题是当一个进程组中过多的进程失效使得这个组中再也不能提供相应的服务，这时就需要某个协议来重建该进程组。总是会有一些进程负责重建工作，问题是当有多个进程同时启动试图重建该组时怎么办？重建协议应该解决这个问题。

组寻址（group addressing）。为了向一个进程组发送一个报文，一个进程必须能够确定它向哪个进程组发送，也就是说每个进程组必须有一个地址，正如一个进程必须有一个地址一样。组寻址的实现方法分为三类：由系统内核实现的方法、由发送进程实现的方法和预测寻址的实现方法。
