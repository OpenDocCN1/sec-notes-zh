# CIH病毒特征

CIH属恶性病毒，当其发作条件成熟时，其将破坏硬盘数据，同时有可能破坏BIOS程序，其发作特征是：

+   1. 以2048个扇区为单位，从硬盘主引导区开始依次在硬盘中写入垃圾数据，直到硬盘数据被全部破坏为止。最坏的情况下面磁盘所有数据(含全部磁盘分区数据)均被破坏。

+   2. 某些主板上的Flash Rom中的BIOS信息将被清除。

CIH病毒属文件型病毒，CIH的原主意是使用Windows的VxD(虚拟设备驱动程序)编程方法，使用这一方法的目的是获取高的CPU权限，CIH病毒使用的方法是首先使用SIDT取得IDT base address(中断描述表基地址)，然后IDT入口的3个入口被改动为指向CIH自己的INT 3中断入口程序，再利用自己产生一个INT 3指令运行地址调用CIH自己的INT 3入口程序，这样CIH病毒就可以获得最高的权限(即环0)。接着病毒将检测到DR0寄存器中的值是否为空，用以判断是否已有CIH病毒驻留，如果DR0值不为0，则表示CIH病毒程序已经驻留，则CIH副本将被恢复先前的INT 3入口，然后退出(这一特点也可以被用来检测CIH程序，以防止它驻留在内存中，但是当病毒在其它可能的原因后强行退出内存，如果判断DR0为0，则CIH病毒将继续进行，其首先将自己的EBX寄存器的值赋给DR0寄存，以生成驻留标记，然后调用INT 20中断，使用VxD call Page Allocate系统调用，要求分配Windows系统内存(system memory)，Windows系统内存地址范围为C0000000h~FFFFFFFFFFh，已选用未被系统所使用的内存区域，如果该内存足够大则驻留在内存中，如果该内存不够则分配到内存的内部，假设到地址空间在C0000000h以上的内存区域，如果内存中存在该病毒，则将该病毒文件中的原先部分多段的病毒代码收集起来，并进行组合后放到申请到的内存空间中。完成组合，释放进程后，CIH病毒再次调用INT 3中断进入CIH病毒的INT 3入口程序，接着调用INT 20中断调用一个IFSMgr_InstallFileSystemApiHook的子程序，用来在文件系统处理函数中挂钩子，以截取文件调用的操作，接着检查IFSMgr_InstallFileSystemApiHook的入口，这样就完成了挂钩子的工作，同时Windows默认于IFSMgr_Ring0_FileIO(InstallableFileSystemManager, IFSMgr)服务程序的入口地址是固定的，以便CIH病毒调用，这样，一旦出现要求打开文件的调用，CIH将在第一时间截获该文件，并判断该文件是否为PE格式的可执行文件，如果是，则感染，如果不是，则放过去，将调用链接正确的Windows IFSMgr_IO服务程序。

CIH不会重复多次地感染PE格式文件，同时可执行文件的只读属性是否有效，不影响感染过程。感染文件后，文件的文件日期和时间信息将保持不变。对于绝大多数PE程序感染后，程序的执行长度也将保持不变。因为CIH将把自身成分多段，插入到程序的空域中。完成驻留工作后的CIH病毒将把原先的IDT中断表中的INT 3入口恢复成原样。
