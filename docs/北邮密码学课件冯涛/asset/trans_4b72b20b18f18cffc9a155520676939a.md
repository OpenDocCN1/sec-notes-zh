## 三个密钥的三重-DES

- 尽管没有对双密钥的三重-DES的实际攻击，但对其还是有疑虑
- 为避免攻击可以使用三密钥的三重-DES
- C = E_{K3}(D_{K2}(E_{K1}(P)))
- 一些基于Internet的应用已经采用三重-DES，如 PGP、S/MIME

## 工作模式

- 分组密码加密固定的分组长度
- 如. DES 加密64-bit的数据分组，密钥长度为56-bit
- 实际中需要加密/解密任意长度数据的方法
- 使用ANSI X3.106-1983 模式 (FIPS 81)定义了4种工作模式
- 为 AES 和 DES扩展为5种模式
- 有分组密码模式和序列密码模式

## 电码本模式 (ECB)

- 消息被分成要加密的独立分组
- 每个分组被替换为一个新值，明文与密文唯一对应，类似密码本，因此得名
- 每个分组独立于其它分组加密
- C_i = DES_K1 (P_i)
- 用途: 单个数据的安全传输

## ECB的优缺点

- 主要用于发送只有几个分组的数据
- 缺陷是由于要加密的消息互相独立
- 重复的消息可能出现在密文中
- 如果消息是结构化的
- 尤其是图像数据
- 或者是有重复的消息，会成为密码本模式分析的问题

## 密文分组链接模式 (CBC)

- 消息被分成几个分组
- 加密操作链接在一起，前面的密文分组和当前的明文分组链接，因此得名
- 使用初始化向量(IV)开始加密
- Cᵢ = DESₖ₁(Pᵢ XOR Cᵢ₋₁)
- C₋₁ = IV
- 用途:大量的数据加密,认证

## 消息填充

- 消息的末尾可能要处理一个较短的数据分组
- 该分组小于密码算法分组的长度
- 用已知的非数据符号填充 (如 nulls)
- 或者用填充字符的个数填充最后分组
- 如. [b1 b2 b3 0 0 0 0 5]
- 表示有3个数据字节,后面5个字节填充+计数
- 消息中或许需要一个特殊的完整分组
- 有其它深奥的模式，这些模式避免了特殊分组的使用

## CBC的优缺点

- 密文分组依赖于前面的所有分组
- 一个分组的任何变化影响后续的密文分组
- 需要初始化矢量 (IV)
- 对发送者和接收者是已知的
- 如果不加密发送，攻击者可能改变第一分组的前几位，进而获得秘密信息
- 因此 IV 必须是一个固定值 (如电子转账应用中) 或者必须在发送其它消息之前，用ECB模式加密后发送

## 密文反馈模式（CFB）

- 消息按照流密码（字符序列）处理
- 分组密码的输出与明文异或
- 密文的结果反馈为下一阶段的输入
- 标准允许反馈任意位数（1, 8, 64 or 128 etc）
- 表示成 CFB-1, CFB-8, CFB-64, CFB-128 等
- 使用分组中的所有位（64 or 128）最有效
```
C_i = P_i XOR DES_{K}(C_{i-1})
C_{-1} = IV
```
- 用途：流数据加密、认证

## CFB的优缺点

- 适用于数据以 bits/bytes 到达
- 最常用的序列（流）密码模式
- 缺点是每n-bits后要做分组加密时需停止
- 在加解密的两端，分组算法用于其加密模式中出现错误后错误扩散到后续分组

## 输出反馈模式 (OFB)

- 消息按照位序列处理
- 加密算法的输出被加到消息上
- 输出被反馈为下一阶段的输入 (因此得名)
- 反馈机制与明文密文相互独立
- 能被预处理
- Cᵢ = Pᵢ XOR Oᵢ
- Oᵢ = DESₖ₁(Oᵢ₋₁)
- O₋₁ = IV
- 用途: 对噪音信道的序列加密

## OFB的优缺点

- 位错误不扩散
- 更易受消息篡改攻击
- Vernam 密码的一种形式，因此从不重复使用相同的（key+IV）序列
- 发送者和接收者必须保持同步，前m-bit反馈
- 研究表明只有完整的分组反馈（例如 CFB-64 和 CFB-128）模式被使用

## 计数器模式 (CTR)

- 尽管类似于OFB，是一种新的反馈模式
- 加密的是计数值而不是反馈值
- 对每个明文分组必须有一个不同的密钥和计数值
- (从不重复使用)
- Cᵢ = Pᵢ XOR Oᵢ
- Oᵢ = DESₖ₁(i)
- 用途:高速的网络加密

## CTR优缺点

- 效率
- 在硬件或软件中能够进行并行加密
- 预处理
- 适用于高速链路
- 能够随机访问加密的数据分组
- 可证明安全性 (和其它模式一样安全)
- 但必须确保从不重复使用密钥/计数值,否则可能破译 (如同 OFB)

## 流（序列）密码

- 逐位处理消息 (一个序列或流)
- 使用伪随机密钥流
- 密钥流与明文按位异或
- 密钥流的随机性完全破坏了消息中的统计属性
- C₁ = M₁ XOR StreamKey₁
- 但不能重复使用序列密钥
- 否则可能恢复消息 (如同密码本)

## RC4

- 由RSA数据安全公司拥有的 一种序列密码
- 由Ron Rivest等设计的,简单而且有效
- 可变密钥长度,面向字节操作的序列密码
- 广泛使用(web SSL/TLS, wireless WEP)
- 密钥构成所有8-bit值的随机变换
- 使用该变换搅乱一次处理一个字节的输入信息

## RC4 密钥方案

- 用 0，…，255 初始化一个数组 S
- 使用密钥去实现混淆
- S 构成了密码的内部状态

```
for i = 0 to 255 do
    S[i] = i
    T[i] = K[i mod keylen]

j = 0
for i = 0 to 255 do
    j = (j + S[i] + T[i]) (mod 256)
    swap (S[i], S[j])
```
