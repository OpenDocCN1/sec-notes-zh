
## RC4 加密

- 连续混淆数组值加密
- 流密钥是从置换中获得的混淆对的和
- 为加密和解密消息的后续字节与 S[t] 异或

```
i = j = 0
for each message byte M_i
i = (i + 1) (mod 256)
j = (j + S[i]) (mod 256)
swap(S[i], S[j])
t = (S[i] + S[j]) (mod 256)
K = S[t]

C_i = M_i XOR S[t]
```

## RC4 安全

- 对已知攻击是安全的，有一些分析，没有实际攻击
- 结果是非线性的
- RC4是序列密码，不能重复使用密钥
- 对WEP有关注,但密钥的处理不是RC4本身

## 总结

- 三重-DES
- 运算模式：ECB, CBC, CFB, OFB, CTR
- 序列密码: RC4

## 加密功能设置

- 主要有两种设置
- 链路加密
  - 加密在每条链路上独立地进行
  - 暗示着链路之间的每次分组交换都要将消息解密
  - 需要很多加密设备,但只要一对密钥
- 端对端加密
  - 由源主机和终端加密数据
  - 各终端共享密钥并且都需要有加密设备

## 加密功能设置

- 当使用端对端加密时,必须让信息头保持明文
  - 这样网络就能正确实现信息的路由
- 因此,尽管信息内容得到了保护,路由信息却没得到保护
- 希望将两者结合起来
  - 端对端加密在整个传输路径上保护数据内容和提供认证
  - 链路加密保护路由信息免受监测

## 加密功能设置

- 能为OSI参考模型的各层设置加密功能
  - 链路加密用于第1层或第2层
  - 端对端加密用于第3,4,6,7层
  - 我们要是往通信层次上边走,那么要加密的信息少了,尽管要用到更多的设备和密钥,但是其安全性却更高了

## 流量分析

- 监测通信双方之间的通信信息流
  - 在军事&商业领域是很有用的
  - 也可以被用来创建隐通道
- 链路加密可以隐藏信息头的具体内容
  - 但网络和端点的通信总量仍然可以被观察到
- 传输填充能进一步隐藏信息流
  - 但却要以连续不断的数据传输为代价

## 密钥分配

- 对于通信参与者A和B, 密钥分配有多种方法：

1. A选择密钥并亲自交给B
2. 第三方选择&交付密钥给A&B
3. 如果A&B以前使用过某密钥进行通信, 其中一方就可以用它加密一个新密钥后再发送给另一方
4. 如果A&B与第三方C均有秘密通道, 则C可以将密钥分别秘密发送给A&B

## 伪随机数发生器 (PRNGs)

- 通常使用确定的算法去产生“随机数”
  - 尽管不是真正的随机
  - 能经受“随机性”检测
  - 称为 “伪随机数”
  - 由 “伪随机数发生器 (PRNGs)”产生

## 线性拟合发生器

- 使用迭代方法:
  $X_{n+1} = (a X_n + c) \mod m$
  - 对于合适的参数值能产生一个长的伪随机序列
  - 适当的标准有:
    - 生成函数是全周期的
    - 产生序列应显得随机
    - 可以用32位算法高效地实现
  - 注意,对于一个较小的数值,攻击者能重构随机序列
  - 存在使重构序列变得更加困难的可能性

## 使用块密码作为PRNGs

- 为满足在密码学上的使用,可以使用块密码产生随机数

- 用主密钥来生成会话密钥作为最终的随机数

- 计数器模式
  X_i = E_{Km}[i]

- 输出反馈模式
  X_i = E_{Km}[X_{i-1}]

## Blum Blum Shub 发生器

- 基于公钥算法
  use least significant bit from iterative equation:
    - x_i = x_{i-1}^2 mod n
    - 其中,n=p.q,并且素数 p,q=3 mod 4
  - 是不可预测的,可通过续位测试
  - 安全性基于N的因子分解困难性
  - is unpredictable given any run of bits
  - 会很慢,因为必须使用非常大的数
  - 用来加密显得太慢,用来产生密钥是很好的选择

## 自然随机噪声

- 最好的随机源来自真实世界中的自然随机噪声
- 寻找一种规则但却随机的事件和监听器
- 通常需要特定的 h/w
- do generally need special h/w to do this
  - 例如，辐射计数器、无线电噪声、音频噪声、二级管热噪声、漏电容、泵放电二级管等
- 在最新的 CPU 相关资料中去查 h/w
- 信号中的偏差或不均匀分布问题
  - 当采样本并使用时，必须得想办法消除偏差
  - 最好在取得的样本中仅使用噪声最强的那些位
