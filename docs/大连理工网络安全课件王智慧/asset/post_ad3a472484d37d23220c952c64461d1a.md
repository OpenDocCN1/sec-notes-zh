
## 密钥管理和分发的要点

- 给安全传输数据的参与者分发密钥，提供分发密钥的方法或协议
- 分发的密钥包括主密钥和会话密钥
- 密钥管理方法因所使用的密码体制（对称密码体制和公钥密码体制）而异
- 公钥证书保证公钥的安全性
- X.509公钥证书的格式
- 公钥基础设施PKI：创建、管理、存储、分发和撤销公钥证书

## 对称加密的对称密钥分发

- A选择一个密钥后以物理的方式传给B
- 第三方选择密钥后物理地传递给A和B
- 如果A和B先前或者最近使用过一个密钥，则一方可以用旧密钥将新密钥加密后发送给另一方
- 如果A和B到第三方C有加密连接，则C可以在加密连接上传送密钥给A、B

一个有n个用户的系统，需实现两两之间通信

| 用户 | 对称密钥配置 |
|------|--------------|
| 用户1 | K1-2,K1-3,...,K1-n |
| 用户2 | K2-1,K2-3,...,K2-n |
| ... | |
| 用户n | Kn-1,Kn-2,...,Kn-n-1 |

n个用户，需要n(n-1)/2个共享密钥

- 主密钥（Primary Key）：又称用户密钥(User key)，是由用户选定或由系统分配给用户的，可在较长时间（相对于会话密钥）内由一对用户（终端与密钥分发中心 KDC）所专用的密钥。
- 会话密钥（Session Key）：即两个通信终端用户在一次通话或交换数据时使用的密钥。当它用于加密文件时，称为文件密钥(File key)，当它用于加密数据时，称为数据加密密钥(Data Encrypting Key)。

## 基于公开密钥体制的对称密钥分发

- 简单的密钥分发 Simple secret key distribution
- 具有保密和身份认证能力的分发 Secret key distribution with confidentiality and authentication
- 混合方案 Hybrid scheme

### Simple secret key distribution

- Merkle的建议：[Merkle 79]

![](img/09e6564ace8d10cc99172928c514fc45_312_0.png)

1. A生成{KUa,KRa}，A→B：(IDa,KUa)
2. B生成随机密钥Ks，B→A：E_KUa(Ks)
3. A解密E_KUa(Ks)得到Ks：D_KRa(E_KUa(Ks))
4. A丢弃{KUa,KRa}，B丢弃KUa

- 通讯前不需存在密钥，通讯后也不存在密钥
- 能抵抗偷听，不能抵抗主动攻击（中间人攻击）

### Merkle协议的中间人攻击

1. A生成{KUa,KRa}, A→B: (IDa,KUa)
2. E截获，生成{KUe,KRe}冒充A→B: (IDa,KUe)
3. B生成随机密钥Ks, B→A: E_KUe(Ks)
4. E截获，解密后再用E_KUa加密Ks→A: E_KUa(Ks)
5. A丢弃{KUa,KRa}, B丢弃KUa

- E获得了Ks，故以后只需进行窃听。
- A、B并不知晓它们被攻击了

### Secret key distribution with confidentiality and authentication

![](img/09e6564ace8d10cc99172928c514fc45_314_0.png)

假定A和B已经获得了双方的公钥：

1. A→B: \( E_{KUb}(ID_A, N_1) \)
2. B→A: \( E_{KUa}(N_1, N_2) \)
3. A→B: \( E_{KUb}(N_2) \)
4. A→B: \( Y = E_{KUb}(E_{KRa}(Ks)) \)
5. B解密Y获得会话密钥 \( Ks = D_{KUa}(D_{KRb}(Y)) \)

### Hybrid Scheme

- 在IBM大型主机上使用
- 仍然使用KDC
- KDC与每个用户都拥有{公钥,私钥}对
- KDC与每个用户共享主密钥(对称密钥密码)
- 会话密钥的分发由主密钥完成
- 主密钥更新由公钥完成

## 三、公钥分发技术

### 公开发布公钥

- 具体方式：
  - 通过亲自交换
  - 通过广播给通信各方
- 缺点：伪造公钥，并公开发布，在受害者发现有人假冒并通知其他用户之前，假冒者可以读取本该发送给受害者的信息

### 公开可访问的公钥目录

- 管理员建立一个可信的目录，其中每个目录项包括各用户的名称和可信公钥
- 通信方通过管理员来注册公钥
- 通信方可以用新的密钥代替当前的密钥
- 用户直接从目录中获取公钥

缺点：攻击管理员的私钥，或者修改目录内容

### 公钥授权

- 通过在线可信服务器获取指定用户的公钥
- 在线可信服务器对公钥进行签名后再传送
- 参与方可验证接收到的签名的真实性
- 缺点：
  - 可信服务器必须在线
  - 可信服务器可能会成为瓶颈
  - 必须建立预定的通信方与可信服务器的通信链接

### 离线服务器和证书的使用

- 公钥证书
  - X.509证书
- PKI
  - 一种安全体系和框架

### 公钥证书

- 目的：使一个实体的公钥可用于其他实体，并能验证公钥的真实性和有效性。
- 是一个由数据部分和签名部分组成的数据结构
  - 数据部分：包括明文数据，最少包括一个公钥和一个参与方的标识符
  - 签名部分：证书颁发机构 CA (Certification Authority) 对数据部分的数字签名，以保证公钥的真实性
- 用户通过公钥证书来互相交换自己的公钥，而无需与公钥管理机构联系
- 公钥证书能以明文的形式进行存储和分配
