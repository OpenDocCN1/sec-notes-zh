3> Player的指针

那么最关键的来了,如何找Player的指针呢?,ce是有mono功能的,我们可以直接hook dll中函数

hookPlayer的任意函数->修改里面的内容(因为是Player的函数所以可以通过this获取到Player的指针)->获取到指针

4> hook 函数选择问题

因为Player的指针是经常变的,比如死亡/回档/重启等等操作都会可能导致Player的指针的变化,这就是为什么ce搜到的值不能用了

- 因为unity有Update的函数,即每一帧都干执行一遍,可以hook这个函数

- 也可以hook其他的函数,如键盘输入时input,或者其他任意Player的指针的变化后执行了的函数

- 更新的越频繁越消耗系统资源(其实也没消耗多少),但是也要保证死亡/回档时能及时更新

- 这里hook的是UpdatePlayerState

        if (!this.actionFlag.Has(ActionFlag.Roll) && !this.actionFlag.Has(ActionFlag.Combat))

也不一定非要在这里在开头第一句也可以,在最后也可以,只要不影响原来的逻辑都是可以的

5> 模板脚本解释

- 
define(address,Player:UpdatePlayerState+10)

修改 292A75BC110 为Player:UpdatePlayerState+10

因为292A75BC110每次启动游戏会变化

- 
define(bytes,48 8B F1 66 0F 57 C0)

48 8B F1 对应Player:UpdatePlayerState+10 - 48 8B F1              - mov rsi,rcx

66 0F 57 C0 对应Player:UpdatePlayerState+13 - 66 0F57 C0            - xorpd xmm0,xmm0  

- 这里为什么要hook2行:

Player:UpdatePlayerState+10才3字节 jmp newmem就是5个字节,一行不行

2行7字节还有2个字节用nop填充

```
address:
jmp newmem
nop 2

-
