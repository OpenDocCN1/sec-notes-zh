## 1.派遣函数

### 目标

理解派遣函数的定义，并且在自己的驱动中编写派遣函数。

### 0x01 什么是I/O，什么是I/O请求包

简单来说，I/O请求就是软件层面向硬件层面的请求。

> I/O请求（Input/Output Request）是指应用程序或操作系统向设备发送的读取、写入、打开、关闭等操作请求。例如，当您打开一个文件时，操作系统会向文件所在的磁盘驱动器发送一个I/O请求，以读取文件的内容。当您向网络发送数据时，操作系统会向网络适配器发送一个I/O请求，以将数据发送出去。

在Windows内核中，I/O请求通常使用I/O请求包（`IRP`）结构体来表示。`IRP`包含了请求的类型、请求的参数、缓冲区地址、I/O状态等信息。当一个I/O请求被提交到内核中时，内核会将`IRP`插入到相应的驱动程序的I/O请求队列中，并调用相应的派遣函数来处理该请求。在派遣函数中，驱动程序需要根据请求的类型和参数来执行相应的操作，并根据操作的结果来更新`IRP`中的状态和返回值。

理解I/O请求的概念和处理方式对于驱动程序的开发至关重要。驱动程序需要处理各种类型的I/O请求，例如读取和写入文件、打开和关闭设备、发送和接收网络数据等。

### 0x02 什么是派遣函数

简单来说，派遣函数就是处理IO请求包`IRP`的一个函数。

> 派遣函数是Windows内核模式驱动程序中的一个重要函数，用于处理操作系统或用户空间应用程序发出的系统调用或I/O请求。派遣函数接收一个`IRP`（I/O请求包）结构体，该结构体描述了应用程序请求的操作类型和相关参数。然后，派遣函数会根据请求的操作类型和参数来执行相应的内核代码，完成请求的操作。在编写驱动程序时，开发人员必须为每个操作类型编写一个派遣函数。

下面是一个简单的派遣函数示例：

```
NTSTATUS DispatchFunction(IN PDEVICE_OBJECT DeviceObject, IN PIRP Irp) {
    // 根据请求的操作类型和参数执行相应的内核代码
    // ...
    // 完成请求的操作后，返回NTSTATUS类型的返回值
    return STATUS_SUCCESS;
}
```

> 在这个示例中，`DispatchFunction`是一个派遣函数，它接收一个`PDEVICE_OBJECT`类型的设备对象和一个`PIRP`类型的请求结构体作为输入参数。开发人员需要根据请求的操作类型和参数来编写相应的内核代码，最后返回一个`NTSTATUS`类型的返回值。在驱动程序中，需要根据需求编写自己的派遣函数。例如，如果驱动程序需要支持文件操作，需要编写读取、写入和关闭文件的派遣函数。如果驱动程序需要支持网络操作，需要编写接收和发送网络数据的派遣函数。在编写派遣函数时，您要参考Windows内核开发文档和相关示例代码，确保代码符合内核编程的最佳实践。

### 0x03 编写派遣函数

我们基于之前`helloworld`的驱动编写。

这里编写了一个只有打印内容的派遣函数。

```
NTSTATUS MyCreate(PDEVICE_OBJECT pDeviceObject, PIRP pIrp){
    // 告诉编译器pDeviceObject参数当前未使用，防止编译器报警
    UNREFERENCED_PARAMETER(pDeviceObject);
    // 打印日志，记录创建请求的到来
    DbgPrint("Create request received!\n");
    // 设置IRP的返回状态为STATUS_SUCCESS
    pIrp->IoStatus.Status = STATUS_SUCCESS;
    // 设置IRP的返回信息为0，表示没有任何返回信息
    pIrp->IoStatus.Information = 0;
    // 完成IRP的处理，将其返回给调用者
    IoCompleteRequest(pIrp, IO_NO_INCREMENT);
    // 返回操作状态，这里设置为STATUS_SUCCESS表示操作成功
    return STATUS_SUCCESS;
}
```

一开始不知道`NTSTATUS`是一个什么类型，所以做了一下参考：

> `NTSTATUS`是Windows内核中广泛使用的一种数据类型，表示操作的执行状态。`NTSTATUS`类型定义在`ntstatus.h`头文件中，并且其值是一个32位的无符号整数。`NTSTATUS`值的最后16位表示操作的类型，例如成功、错误、信息等。低16位是错误码，它可以提供有关操作失败的详细信息。
> 每个`NTSTATUS`值都可以使用`NTSTATUS_FROM_WIN32`或`HRESULT_FROM_NT`等宏将其转换为WIN32或COM错误代码。在内核模式编程中，驱动程序通常需要在执行操作时返回`NTSTATUS`类型的值，以告知操作的执行状态。例如，当驱动程序成功处理I/O请求时，它将返回`STATUS_SUCCESS`值，表示操作成功完成。如果操作失败，则驱动程序需要返回适当的`NTSTATUS`值，以便操作系统或其他驱动程序可以根据该值来识别和处理错误。在编写驱动程序时，开发人员需要仔细阅读Windows内核编程文档，了解`NTSTATUS`类型的各种取值及其含义，并在驱动程序中正确处理和返回`NTSTATUS`类型的值，以确保驱动程序的正确性和可靠性。

## 2.驱动对象及设备对象

### 目标

理解驱动对象及设备对象的基本定义，使用相关工具观察驱动对象及设备对象

### 0x01 基本定义

当我们编写 Windows 驱动程序时，驱动对象和设备对象是非常重要的概念。驱动对象代表整个驱动程序，而设备对象则代表驱动程序所管理的一个设备（一个驱动对象里可以有很多设备对象）。下面简单介绍一下这两个对象的基本定义：

驱动对象：

> 驱动对象是一个由操作系统内核为驱动程序所创建的数据结构，它代表整个驱动程序。它包含了驱动程序所需要的信息，例如驱动程序入口点函数地址、设备对象列表、驱动程序所使用的资源等。在驱动程序中，我们可以通过定义和操作驱动对象来实现对整个驱动程序的管理和控制。

设备对象：

> 设备对象则是一个由驱动程序所创建的数据结构，它代表驱动程序所管理的一个设备。设备对象包含了设备的一属性信息，例如设备类型、设备特征等。此外，设备对象还包含了操作函数指针，用于处理各种设备请求，例如读、写、控制等。在驱动程序中，我们可以通过定义和操作设备对象来实现对设备的管理和控制。
