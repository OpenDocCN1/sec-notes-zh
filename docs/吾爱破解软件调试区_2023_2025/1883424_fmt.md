
# [系统底层] 堆利用详解：largebin attack

- 原帖: `https://www.52pojie.cn/forum.php?mod=viewthread&tid=1883424`
- 抓取时间: `2026-11-01T21:55:08`

## 简介

> 

本文参考自 `how2heap` 和 `malloc.c` 源码进行介绍，介绍 `2.23` 和 `2.35` 情况下的 `largebin attack`

### 漏洞原因

`Use-After-Free`，`overflow write`

### 适用范围

- `libc 2.23` - 至今
- 可以伪造 `largebin` `chunk` 的 `bk_nextsize` 指针

### 利用原理

漏洞利用基于伪造 `bk_nextsize` 指针，类似于未排序块攻击。攻击者通过篡改已释放的大块的 `bk_nextsize` 指针，利用大块排序机制达到攻击效果。攻击涉及到对大块的多次请求、释放和重新分配，通过覆写已释放大块的指针，以触发排序操作，并最终使目标被覆写。

### 相关技巧

- `libc 2.30` 加入了对排序时非最小 `chunk` 情况下的双链表完整性检查
- `libc 2.30` 之前，可以通过整理 `largebin` 非最小 `chunk` 完成利用
- `libc 2.30` 之后，需要通过整理 `largebin` 中最小 `chunk` 完成利用

### 利用效果

- 执行一次任意地址写，写入一个 `chunk` 的地址
- 成功利用该漏洞可以作为其他漏洞利用技术的入口，例如启用多个 `fastbin` 攻击，覆写 `global_max_fast` 变量等。

### 探究：在 `malloc` 触发漏洞的时候，经历了哪些过程？

本次 `malloc` 中经历的过程简述（完整过程见参考资料[4]中的博客文章）：

- 大小检查，不满足 `fastbin`，继续
- 大小检查，满足 `smallbin`，但是 `smallbin` 中没有 `chunk`，继续
- `unsortedbin` 处理过程，从后向前遍历 `unsortedbin`，取出一个 `chunk`，第一轮
  - 大小合法性检查：不能太小也不能太大
  - 判断是否能使用 `remainder`，此时申请的大小是 `0x90`，对应到 `chunk` 大小就是 `0xa0`，`unsortedbin` 的大小依次分别是 `0x511` 和 `0x391`（`last_remainder`）
  - 当前 `chunk` 是 `0x511` 的那个，不是 `last_remainder`，所以会跳过 `last_remainder` 的过程
  - `unsortedbin` `chunk` 断链
- 大小没有精确匹配，该 `chunk` 存入 `largebin`，并进行排序整理，把同组内按照从小到大进行排序
  - 此时，该 `largebin` `chunk` 会排入刚刚的 `largebin` `chunk` 之后，比较大小没有对 `size` 合法性的检查，`size` 被篡改了也不会影响流程，也没有双链表完整性检查
- `unsortedbin` 处理过程，第二轮，下一个 `chunk` 是 `last_ramainder`，`chunk` 会从 `remainder` 机制中分配出去
- 函数返回

可以看到，这里先判断大小，如果是`largebin`大小，就先进行排序：

- 在对应的`bin`中找到刚好比自己大的`chunk`（`fwd`），根据`fwd`获取到`bck`
- 然后在`fwd`和`bck`两个`chunk`中间，`nextsize`链表进行插入
- 最后在把`fd`，`bk`这个链表插入到两个`chunk`中间

注意：这里对`chunk size`没有任何校验，即使被篡改了，也会把修改后的值当正常来用，以及，这里对双链表插入操作没有任何检查，双链表如果损坏，可造成任意地址写入的问题

篡改`bk`和`bk_nextsize`的结果：

- 在`bk`指向地址-0x10处写入一个堆地址（被整理进去的`unsortedbin chunk`的地址）
- 在`bk_nextsize`指向地址-0x20处写入一个堆地址（被整理进去的`unsortedbin chunk`的地址）

## 4> 总结

综上，进行这种利用需要满足的条件：

- 有`largebin chunk`，且大小是`bin`中最小的，能修改`bk`和`bk_nextsize`指针
- 释放一个大一点的`unsortedbin`到该`largebin`中，使其在触发`sorting`阶段被整理进入`largebin`中

- largebin chunk 的 `bk_nextsize` 可以被修改
- 需要被整理进 largebin 的 unsortedbin chunk size 为 largebin 中的最小
