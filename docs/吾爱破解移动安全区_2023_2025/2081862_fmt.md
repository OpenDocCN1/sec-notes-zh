## 前言

群友分享的一款游戏辅助，发现这款辅助的验证逻辑比较有趣。它使用了一个混淆的动态库（`3.dylib`）来处理激活码验证，并且验证失败后会直接强制退出应用。

本文将详细记录完整的破解流程：

- 使用 Frida 进行动态分析和定位关键函数。
- 编写 Frida 脚本验证猜想。
- 使用 Logos 语法编写 Tweak 插件，实现永久破解。

## 一、环境准备

- 设备：越狱 iPhone/iPad（iOS 14+）
- 工具：
  - Frida（动态调试）
  - Theos / MonkeyDev（插件开发）
  - Mac 电脑（用于分析和编译）

## 二、初步分析与定位

### 1. 界面与进程分析

打开应用，点击某些功能会弹出“请输入激活码”的弹窗。随便输入一个码（如 `123456`），点击验证后，应用提示失败并直接闪退。

首先使用 Frida 查看当前运行的进程和加载的模块：

```bash
frida-ps -Ua | grep CPU
# 得到 PID 和 BundleID: com.suwen.DeviceInfo
```

### 2. 模块扫描

在加载的模块中，发现了一个命名非常可疑的动态库：`3.dylib`。通常这种单字母或数字命名的库都是核心逻辑所在。

我们挂载 Frida 脚本去遍历这个库里的类：

```javascript
// 简化的分析片段
var modules = Process.enumerateModules();
modules.forEach(function(m) {
    if (m.name.includes("3.dylib")) {
        console.log("找到dylib: " + m.name);
    }
});
```

经过分析，我们在 `3.dylib` 中定位到了一个混淆类 `xx`。查看它的方法列表（可以用 `frida-trace` 或 `ObjC.classes.xx.$ownMethods`），发现几个关键方法：

- `+ [xx exitWithTip:]`：看名字就知道是验证失败后的退出函数。
- `+ [xx deleteCodeFromSandbox]`：验证失败后删除本地保存的激活码。
- `+ [xx CQQ77280082]`：混淆方法，疑似验证检查。
- `+ [xx IQQ77280082:]`：混淆方法，疑似处理输入。

## 三、验证逻辑分析（Frida Hook）

我们编写一个 Frida 脚本来追踪这些方法的调用流程。

观察到的流程：

- 点击验证。
- 调用 `IQQ77280082:` 进行网络/本地校验。
- 校验失败，调用 `exitWithTip:` 传入错误提示。
- 调用 `deleteCodeFromSandbox` 清除数据。
- 应用退出。

破解思路：

要想实现“随便输入都能成功”，我们需要做两件事：

- 防御：拦截 `exitWithTip:`，阻止应用退出，并拦截 `deleteCodeFromSandbox` 保留我们也随便输入的激活码。
- 进攻：找到判断激活状态的函数 `CQQ77280082`，强行让它返回 `1`（`True`）。

### Frida 验证脚本（`bypass.js`）

```javascript
if (ObjC.available) {
    var xx = ObjC.classes.xx;

    // 1. 拦截退出，并自动关闭弹窗
    Interceptor.replace(xx["+ exitWithTip:"].implementation, new NativeCallback(function(arg1) {
        console.log("拦截退出指令！");
        // 获取 UIWindow 并关闭最顶层的 UIAlertController
        ObjC.schedule(ObjC.mainQueue, function() {
            var win = ObjC.classes.UIApplication.sharedApplication().keyWindow();
            var vc = win.rootViewController();
            while (vc.presentedViewController()) {
                vc = vc.presentedViewController();
            }
            vc.dismissViewControllerAnimated_completion_(true, null);
        });
    }, 'void', ['pointer']));

    // 2. 伪造激活状态
    Interceptor.attach(xx["+ CQQ77280082"].implementation, {
        onLeave: function(retval) {
            retval.replace(ptr(1)); // 强行返回 True
        }
    });

    console.log("Hook成功!");
}
```

运行脚本后测试，随便输入激活码，点击验证，弹窗消失，应用未退出，破解成功！

## 四、Tweak 开发（Logos）

为了实现从“越狱临时破解”到“永久插件破解”，我们将上述逻辑转换为 iOS Tweak 代码。

### 1. 项目配置（plist）

确保 Tweak 只注入目标应用：

```
Bundles
    com.suwen.DeviceInfo
```

### 2. 核心代码（`Tweak.xm`）

```objc
#import

// 配置常量
static NSString *const kToastTitle    = @"垃圾星空";
static NSString *const kToastSubtitle = @"MacXK破解";
static NSTimeInterval const kToastDuration = 2.0;

// 目标类声明（混淆类 xx）
@interface xx : NSObject
+ (void)exitWithTip:(NSString *)tip;
+ (void)deleteCodeFromSandbox;
+ (int)CQQ77280082;
+ (int)heartBeatCheck;
@end

// --- Hook 逻辑 ---
%hook xx

// 1. 拦截退出函数
+ (void)exitWithTip:(NSString *)tip {
}

// 2. 拦截删除操作
+ (void)deleteCodeFromSandbox {
}

// 3. 核心：强制返回激活状态
+ (int)CQQ77280082 {
    return 1; // 1 = True，欺骗 App 已激活
}

// 4. 心跳检测 Bypass
+ (int)heartBeatCheck {
    return 1;
}

%end
```

## 五、总结

本次破解主要利用了以下几点：

- 关键函数定位：通过 Dylib 分析找到混淆类 `xx` 和退出函数 `exitWithTip`。
- 逻辑阻断：直接 Hook 掉退出函数，应用就成了“不死之身”。
- 状态伪造：修改 `bool` 返回值的 `check` 函数，实现假激活。

这是 iOS 逆向中非常经典的 Hook & Patch 思路。希望这个教程对大家学习 iOS 逆向和 Tweak 开发有所帮助！
