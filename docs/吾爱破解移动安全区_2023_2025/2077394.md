### 定位

首先直接去跑一遍通用的so文件定位脚本，去hook `dlopen`函数查看是否是在native检测

```
let isFind = false
function hook_dlopen(func_name,target_so_name,call_back) {
    let addr = Module.findExportByName(null,func_name)
    if (addr != null) {
        Interceptor.attach(addr,{
            onEnter:function (args) {
                this.path = args[0].readCString()
                console.log('func_name onEnter',this.path)
                if (this.path.indexOf(target_so_name) !== -1) {
                    console.log("找到你了")
                    isFind = true
                }

            },
            onLeave:function (retval) {
                console.log('func_name onLeave',this.path)
                if (isFind) {
                    call_back()
                    isFind = false
                }
            }
        })
    }
}

    hook_dlopen("android_dlopen_ext","",hook_func)

}
```

### 分析

从图中可以看到，so文件并没有执行`onLeave`函数，就开始崩溃掉，猜测可能是在`init_array`或者`init`段存在相关frida检测（为何不是`jni_onload`函数，AI求助后`jni_onload`函数的执行时机是在`dlopen`函数离开之后执行），将so文件拖到ida开始分析，首先去找`init_array`段，ida中找到通过视图view找到segement段，如图：

![](https://attach.52pojie.cn/forum/202512/03/151347obddzfx2lkgq8llp.png)

发现并没有`init_array`,甩给智多星AI分析一通，学到了新的名词（节头被去除（Section Stripped）），简单来说：开发者为了防止被逆向，把 `.init_array`、`.text`、`.data` 这些**“路牌”**全部拔掉了。所以 IDA 只能识别出最底层的 `LOAD`（加载段），也就是单纯的内存块。简直天书一样，都点了图中`Load`的数据段，`alt+b`快捷键搜索十六进制的`19 00 00 00`，（为什么是这个数，又去补了功课，这是 ELF 文件格式标准 规定的“死规矩”。

在 ELF 标准文档里，定义了一系列的常量：

```
DT_NULL = 0
DT_NEEDED = 1
...
DT_INIT_ARRAY = 25
```

`25` 换算成十六进制，就是 `0x19`。

只要是标准的 ELF 文件（Linux/Android），`25` 号标签永远代表“初始化数组”，拷贝过来的），果然搜索到了定位如图：

![](https://attach.52pojie.cn/forum/202512/03/151349f58vxfnnbf1fjex8.png)

进入到`DT_INIT_ARRAY`函数地址内，其数据表如图：

![](https://attach.52pojie.cn/forum/202512/03/151351gt0hkktkh0mfzklh.png)

三个函数地址，其检测frida相关的函数可能就在其中，依次点击进去分析其代码，发现只是简单的赋值初始化相关操作（省略），并没有检测相关代码。既然在`init_array`找不到，开始寻找`init`，根据上图可看到其地址`0xBF39`，快捷键`G`跳转后进行分析，部分代码如下：

```
v2 = getpid();//读取进程
sprintf((char *)&v17, "/proc/%d/cmdline", v2);
v11 = fopen((const char *)&v17, "r");
```

看到`fopen`相关函数，本能下反应可能是读取了文件去检测frida，立马开始用脚本进行尝试拦截：

```
function hook_anti_debug() {
    var fopen_addr = Module.findExportByName("libc.so", "fopen");

    if (fopen_addr != null) {
        Interceptor.attach(fopen_addr, {
            onEnter: function (args) {
                this.path = args[0].readCString();
                // 监控它是否在读取敏感文件
                if (this.path.indexOf("/proc/") !== -1 && 
                   (this.path.indexOf("cmdline") !== -1 || 
                    this.path.indexOf("maps") !== -1 || 
                    this.path.indexOf("status") !== -1)) {
                    console.log("!!! 拦截到敏感文件读取: " + this.path);
                    // 标记这次调用，准备在 onLeave 里修改结果
                    this.should_block = true;
                }
            },
            onLeave: function (retval) {
                if (this.should_block) {
                    // 强制返回 0 (NULL)，告诉它“文件打开失败”
                    retval.replace(ptr(0));
                    console.log(">>> 已阻断检测，返回 NULL");
                }
            }
        });
    }
}
```
