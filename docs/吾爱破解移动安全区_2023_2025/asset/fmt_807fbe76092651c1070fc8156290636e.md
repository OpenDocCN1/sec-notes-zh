
# 进入 Android Kernel 根目录

```bash
cd android-kernel
mkdir tools
ln -sf aosp/system/tools/mkbootimg tools/mkbootimg
```

接下来在根目录下可以直接运行 `build/build_bootimg.sh`。注意，不要进入到 `build` 里再执行 `./build_bootimg.sh`，因为可能会找不到 `tools/mkbootimg`。

然后你会在 `out/dist` 下发现 `boot.img`。

关于合并的 ramdisk 文件叫 `ramdisk.gz`，打开虽然只会显示 boot ramdisk，但如果大小是之前的两倍，那么就应该是合并过 vendor ramdisk 的。

## 刷入

如果 `fastboot boot boot.img` 没问题，那么进行刷入：`fastboot flash boot boot.img`。

## 总结

之前说了很多，其实本次章节才是正确操作。

总结点如下：

### 内核配置

内核配置主要看 `.config`，里面包含通用配置，以及特定架构部分的配置，需要覆盖的话需要实现 4 个步骤：

- `make ARCH=arm64 xxx_defconfig` 获取对应架构的 `.config`
- `make ARCH=arm64 menuconfig` 按照 `.config` 进一步配置，此时会打开配置界面
- `make ARCH=arm64 saveconfig` 根据 `.config` 生成 `defconfig`
- `mv|cp defconfig arch/xxxx/xxx_defconfig` 覆盖架构配置

### 内核模块

供应商内核模块除了加载 vendor 分区中的 `/vendor/lib/modules` 位置外。

其实还会通过 vendor ramdisk 中的 `/lib/modules` 进行加载，它会读取 `/lib/modules/modules.load` 配置文件，这是我们可以推送对应内核模块的关键所在。

对于 GKI 内核来说，一般是 `boot.img` 版本 3 以上。

其 vendor ramdisk 是单独存放在 `vendor_boot` 里面的，这种更容易自定义。

而对于本次来说，也就是非 GKI 内核，我们需要将 boot ramdisk + vendor ramdisk 合并成 1 个，并将合并的 ramdisk 参与 `mkbootimg` 打包，生成的 `boot.img` 才是我们刷入的重点。
