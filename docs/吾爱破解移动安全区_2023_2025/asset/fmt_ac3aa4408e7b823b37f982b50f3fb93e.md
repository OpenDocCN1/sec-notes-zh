# 2. bypass 三進程保護

要先bypass掉`libcompatible.so`的反調試，也能繼續動調後面的`libstub.so`。

## 2.1 bypass 嘗試

嘗試直接`patch`掉`anti_debugging()`。

```
function hook_anti_debugging(base) {
    Interceptor.replace(base.add(0x18C148), new NativeCallback(function (arg0) {
        console.log("[hook_anti_debugging] a0: ", hexdump(arg0.readPointer()));
        return ptr(0);
    }, 'pointer', ['pointer']));
}
```

但報了`SIGSEGV`的錯，報錯時的`PC`在`0x7130`，十分奇怪。

![](https://attach.52pojie.cn/forum/202509/20/173111playqxzizlki1lkx.png)

用`frida` + `IDA`動調後發現報錯點在下圖這裡。

![](https://attach.52pojie.cn/forum/202509/20/173112ozoivauffaejuou1.png)

這種情況有兩種可能性：

- `0x7130`存放在某個全局變量`a`中，而`anti_debugging()`中會修改`a`的值為某個函數地址。
- `anti_debugging()`中注冊了`SIGSEGV`的信號回調函數。
