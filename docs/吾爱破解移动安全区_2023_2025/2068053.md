## c-sktrace：基于 C 实现的 sktrace 性能优化

### 前言

这是一个学习性质的项目，研究如何通过 Frida 的 CModule 实现高性能指令追踪。虽然 Frida 官方已经有了 [frida-itrace](https://github.com/frida/frida-itrace) 这个成熟方案，但直接用 CModule 手写可以更深入理解 Stalker 的工作原理和性能优化思路。

项目地址：[//github.com/vwww-droid/c-sktrace](https://github.com/vwww-droid/c-sktrace:https)

### 解决了什么问题

原始的 JavaScript 实现在进行密集指令追踪时存在严重的卡顿问题，主要体现在：

- 热代码路径卡顿：追踪循环体、频繁调用的函数时响应缓慢

- 数据输出延迟：大量指令执行后才能看到结果

- 目标进程被拖慢：被追踪的应用明显变慢甚至无响应

通过 C 实现后，性能提升约两三个数量级（没细测，不过提升明显），实现了无卡顿的实时追踪。

### 性能瓶颈分析

                    })

4> Runtime 阶段开销

```
目标代码执行到被 trace 的指令
    ↓
Callout 触发：Native 代码暂停
    ↓ 切换到 JS 引擎
执行 JS 回调函数
    ↓ JSON 序列化 context
调用 send()（进程间通信）
    ↓ 切回 Native
恢复目标代码执行

示例：追踪一个执行 10,000 次的循环

- 每次循环 before + after callout = 2 次切换

- 总计：20,000 次 Native ↔ JS 引擎切换

4> 引擎切换的开销

每次切换需要：

- 保存/恢复 CPU 上下文（所有寄存器）

- 切换 JS 引擎执行上下文

- 数据序列化/反序列化（context 对象 → JSON）

- 进程间通信

还是很大的性能消耗

3> 解决方案：CModule + Python 异步处理

4> 核心思路

既然无法消除所有 JS 交互，那就：

- C 层：只负责快速读取并输出寄存器值

- Python 层：异步接收数据并进行比较、统计

4> 优势

- ✅ 消除 JSON 序列化开销

- ✅ 使用简洁的管道分隔格式

- ✅ C 层只做读取，稳定高效

- ✅ Python 异步处理不阻塞 trace

def on_message(self, payload):
    type = payload['type']

    if type == 'c_output':
        message = payload['message']

        if '|' in message:
            # 寄存器信息
            parts = message.split('|')
            if len(parts) == 34:
                addr = parts[0]
                x_regs = [int(parts[i], 16) for i in range(1, 30)]
                fp = int(parts[30], 16)
                lr = int(parts[31], 16)
                sp = int(parts[32], 16)
                pc = int(parts[33], 16)

                ctx = Arm64Ctx(pc, sp, *x_regs, fp, lr)

                self.inst_dict[addr].cal_regs_change(self.pre_ctx, ctx)

            # 指令信息
            parts = message.split('\t')

                inst = Inst(addr, addr, 4, mnem, op)

3> 总结

为什么慢？

- 每条指令执行时 Native ↔ JS 切换开销巨大

- 热代码路径中累积成灾难性性能损失

怎么改？

- 用 CModule 把 transform 和 callout 实现为 C 代码

- C 层只做数据采集，Python 层做复杂处理

- 保持在 Native 层执行，消除引擎切换

效果？

- 密集 trace 场景下无卡顿

- 实时输出响应快速

- 目标进程基本不受影响
