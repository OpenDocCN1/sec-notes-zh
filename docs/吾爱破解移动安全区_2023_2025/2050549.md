方案一

存档注入
趣打印在每次启动时会弹窗，但只要用户点击关闭按钮，弹窗就不会再次弹出。

我们很容易想到，这与我们的游戏存档十分类似。当用户执行某些操作时，软件会通过在其私有目录下的 shared_prefs 文件夹内存储某些特征文件或标识，以记录用户的进度或操作。这是很多游戏通用的手法。

我们可以尝试找到这种文件，依旧是用我们的算法助手，设置如下：

![](https://attach.52pojie.cn/forum/202508/02/161529gcpkv42ts55t01xv.jpg)

通过 hook 软件的 get 和 put 来对数据库文件进行定位，平常可能不怎么用，但关键时刻还是能派上大用场。

再次打开软件，待弹窗弹出，返回算法助手查看情况：

![](https://attach.52pojie.cn/forum/202508/02/161532ery5onclzunznlmy.jpg)

我们可以看到软件在弹窗前读取了很多配置，逐个查找，可以找到这样一条可疑的配置文件。

进入：

![](https://attach.52pojie.cn/forum/202508/02/161534rqaj6i3086i8hcqx.jpg)

这里的 kdpklf 就是配置名称，从名字来看不像是系统的，传递的数值是默认的 0。这时我们不妨重新启动软件，点击弹窗使其消失，再返回算法助手查看该读取配置方法：

![](https://attach.52pojie.cn/forum/202508/02/161536xg8qqybsrealeb33.jpg)

我们惊喜的发现，当我们永久关闭弹窗时，该配置文件中的返回值从默认的 0 变为了 494 ，此时弹窗不再弹出。

我们用 MT 管理器定位到该文件所在位置：

/data/data/com.dynamixsoftware.printershare/shared_prefs/.xml

![](https://attach.52pojie.cn/forum/202508/02/161605ix77f9z33f43qmqm.jpg)

打开xml文件，将此时的 494 修改为 0 。

![](https://attach.52pojie.cn/forum/202508/02/161515s2tx365y2zmf51t4.jpg)

![](https://attach.52pojie.cn/forum/202508/02/161612quzq0u2e6h8i6uee.jpg)

重启软件，发现弹窗再次弹出。这就证明了我们的猜想。

现在就可以下结论了，当软件第一次启动时，软件会检查 /data/data/com.dynamixsoftware.printershare/shared_prefs/.xml 文件是否存在。而当用户点击关闭键时，软件则会自动生成这个文件，内部值为 494 。若该文件不存在，则直接弹窗；若存在，且配置文件内的值为 494 ，那么就可判断用户已经按下关闭键，从而不再弹窗。

这完全符合存档注入的条件，我们直接使用存档注入工具，但发现经工具注入后，软件会闪退。猜测是由于函数抽取的原因，导致工具不能正常的向 onCreate 里添加调用函数。

工具添加不了，咱们就手动添加。

```
因为 onCreate 被抽取，所以我们无法直接添加调用代码，那么我们就在 onCreate 方法下直接写一个 onStart 方法：

```

在这里我想有必要普及一下安卓 Activity 生命周期。用官方的话来说，为了在 Activity 生命周期的各个阶段之间导航转换， Activity 类会提供六个核心回调集： onCreate(), onStart(), onResume(), onPause(), onStop() 和 onDestroy()。系统会自动调用这些回调，当 Activity 进入新状态时，会同时触发每一个回调。我们比较熟悉的 onCreate 方法的优先级是最高的，但是 onStart 方法仅次于 onCreate 方法，我们只需在主类中添加 onStart 声明，系统就会帮我们自动调用。

![](https://attach.52pojie.cn/forum/202508/02/161607nkll1c5vi5l1hjxj.png)

所以，就算 onCreate 方法我们修改不了，我们也可以主动添加一个 onStart ，里面写 doCopyAssets 方法的调用，使软件在刚启动时将软件包 assets 文件夹内的 .xml 文件拷贝至 shared_prefs ，从而达成变相去除弹窗的效果，这样操作的优先级也是足够的。

最后，我们只需要将修改后的 .xml 文件手动拷贝到软件包 assets 文件夹内，编译、签名、安装即可。

![](https://attach.52pojie.cn/forum/202508/02/161609b7az7l909a09v098.jpg)

到测试阶段，发现第一次打开软件仍然弹窗，但是杀后台后，第二次打开就不弹窗了。

![](https://attach.52pojie.cn/forum/202508/02/161510l3rb33nfanxe64x4.jpg)

之前提到，软件第一次启动会检测 .xml 文件存在与否，现在看来这个判断就存在于被抽取的 onCreate 方法，而 onCreate 的优先级高于 onStart，所以第一次判断时，我们在 onStart 中定义的复制方法还未被调用，这就导致第一次还会弹出窗口，而再次打开窗口消失。

一点点小瑕疵没什么关系，当然如果大家想在第一次启动时直接去除，存档注入方法仍然适用。我们只需要用添加启动图或类似云注入等工具，替换原软件的第一入口，再于替换后的入口 onCreate 中插入复制方法调用即可。只是由于篇幅和时间限制，我就不细说了，各位可以自己折腾(其实是懒

方法二

Hook大法

既然弹窗都能被检测到，那么把它 Hook 掉也就没什么问题了。Hook 方法有的时候才是最实用的，因为有些软件会上非常恶心的加固。

我们再回算法助手，观察日志，可以看到窗口的文本竟然是可 Hook 的明文，这里我们可以直接使用算法助手或 SimpleHook 自带的屏蔽弹窗功能。但这样未免太偷懒，我就是想没事找事。

于是我决定自己手搓一个 Xposed 模块。我们用手机端的 AIDE pro 作为范例。
