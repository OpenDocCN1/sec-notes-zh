二：回溯网络请求

1.查看是谁调用了m2144这个方法；因为混淆，一眼根本看不出来是谁，只能一个个试，但是运气不错，第二个就是

![](https://attach.52pojie.cn/forum/202407/31/212139njvgt08jjorjo4gt.png)

2.我们直接hook看看是不是；可以看到public static java.lang.String f(java.lang.String r33, int r34, java.util.Mapjava.lang.String, java.lang.String> r35)这个方法第一参数就是网络请求的地址，第二个是0，第三个是个object,而且它的返回值就是服务器的响应信息；说明这个方法就是用来发送网络请求并且返回网络响应

![](https://attach.52pojie.cn/forum/202407/31/212335dybqtgyabtf1zfga.png)

![](https://attach.52pojie.cn/forum/202407/31/212611x3b6d0dpmkz0ykdz.png)

3.继续跟进看看是谁调用了它；我们继续hook它看看都有啥有用的信息；m5181就是获取请求地址，0，还有输入的卡密信息，然后调用f()返回服务器的响应信息；我们最终的目的是找到判断服务器响应的代码，然后修改它，继续回溯

![](https://attach.52pojie.cn/forum/202407/31/213511pxcs63y6qq0u01z0.png)

![](https://attach.52pojie.cn/forum/202407/31/213824m1t8981c6ftaubot.png)

三：回溯服务器响应的判断代码

1.查看是谁调用了m5181，可以发现有两个调用，但是第一个就是我们刚才才看的cd.m8.f()中的，我们直接看第二个

![](https://attach.52pojie.cn/forum/202407/31/214805x6w6vtq99iycz464.png)

2.在public static /* synthetic */ void e(String str, Map map, f3 f3Var)中m5181的值被传给str4,之后有两处关键点对str4（也就是服务器的响应信息）进行判断和处理，我们先查看第一次str4做判断的地方(C0120.m3149(str4))

![](https://attach.52pojie.cn/forum/202407/31/215921nbqpvpvpkeytp1zt.png)

3.直接跟进，卧槽！！！布尔值！！！难不成就是它？？？直接hook让它返回true试试！！！其实我当时看见布尔的那一刻，我高兴坏了，以为这个就是判断服务器响应信息的，没想到啊，它是用来判断是否输入卡密的

4.排除了一个，就只剩最后一个 C0118.m3008(f3Var, str4)，这里肯定就是对服务器的响应进行提取然后判断；直接跟进看看

![](https://attach.52pojie.cn/forum/202407/31/221857tnd1bdlot11dhbzj.png)

5.结果发现m3008里面先进行一个判断，然后再执行((f3) obj).c(obj2)，跟进去后发现f66是定值-365，之后hook发现C0145.m4569()的值是定值553，说明它一定执行了((f3) obj).c(obj2)，我们直接跟进c看看

四：大胆尝试

1.思考本质：

这个app的本质不就是获取用户输入的卡密然后发送给服务器进行验证，然后服务器返回结果，之后app再从服务器返回的结果中来判断是否成功

2.猜想：

如果我直接修改服务器返回的结果呢？我管它服务器返回啥，我直接自己去自定义一个成功的返回值不就行了嘛

3.实践：

3-1.修改msg的值为“卡密正确”，可以看到在只修改msg值的时候，app会显示卡密正确，并且没有出现闪退报错等情况，但是也只是改变了消息，并没有实现功能

![](https://attach.52pojie.cn/forum/202407/31/225604ii6isgiik4xkdskt.png)

3-2.修改datas的值，当它的值为一个时是正常的，但是有两个后就报错了，说明datas的值可能就是是一个

![](https://attach.52pojie.cn/forum/202407/31/230207qd05xjj7vcehhu0e.png)

![](https://attach.52pojie.cn/forum/202407/31/230318pb405g4fq4fga2a9.png)

3-3.修改code的值，我尝试修改了好几个数字，但都是正常的，并没有报错

![](https://attach.52pojie.cn/forum/202407/31/230602fct8t7cc7qut7qd7.png)

3-4.ts的值跟code的值一样，修改多次依然正常，而且仔细看就知道它是个时间戳，我们直接修改status的值；将status的值修改为1后，app成功完成[破解](https://www.52pojie.cn/)！！！并且一切功能全部正常使用

![](https://attach.52pojie.cn/forum/202407/31/231020frv2uevln56lujx8.png)

![](https://attach.52pojie.cn/forum/202407/31/231152kere5uxkvslz6zcs.png)

总结：此app的卡密验证就是验证服务器返回值中的status的值是否为1，如果为1，卡密正确，如果为0，卡密错误；虽然它做了代码混淆，但是它的包都是明文，而且只判断服务器返回中status的值，这就给了我很大的运气完成了这次破解，这也是我首次完成对混淆代码的破解，虽然有很大的运气成分，对于混淆代码，只要慢慢分析，还是可以知道它的逻辑的，然后再慢慢hook不断验证猜想，你也可以完成对混淆代码的破解，感谢支持，大家互相学习学习
